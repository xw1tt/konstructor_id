# Реестр ИД и сборка комплекта в один PDF; замечания к печати

Дата: 19.10.2026
Образец: комплект «Монтаж кабеля» (76 стр.): титул — стр. 1, корешки — стр. 2, реестр — стр. 3–4,
документы — стр. 5 и далее. Дополняет спецификации книги объекта, печати СБД и плана 6.

## 1. Решения

| Вопрос | Решение |
|---|---|
| Состав комплекта (Том/Часть) | Несколько актов: пользователь перечисляет акты комплекта |
| Состав и порядок реестра | Кнопка «Заполнить из актов» раскладывает строки в таблицу «РеестрИД»; пользователь правит, переставляет, добавляет свои; сборка идёт строго по таблице |
| Сканы | Папка сканов (поле «Объекта») + имя файла в столбце «Скан»; прикреплённые через панель файлы (ссылка на сервер) тоже работают |
| Титул и корешки | Генерируются; у комплекта галочки «Титул», «Корешки» |
| Нумерация «л.» | С первого документа после реестра (ВОР = л. 1, как в образце); на страницы ничего не наносится |

## 2. Замечания к печати (до реестра)

1. **Представители** — повторы ФИО и роли допускаются: нет ни подсветки повтора на листе, ни ошибки
   «Значение повторяется» при печати. Ссылки по ФИО (подписанты ВОР) берут первую строку с этим ФИО.
   Подсказка столбца «ФИО» больше не требует уникальности.
2. **Договор подряда и его дата** необязательны: в «Объекте» розовая подсветка пустого значения и «*» в
   карточке — только у «Наименования объекта», «Застройщика» и «Лица, осуществляющего строительство».
3. **Дата документа качества** необязательна. В РИМ и реестре пустая дата печатается «б/д»; в п.3 АОСР
   дата просто опускается.
4. **РИМ**: у материала с несколькими документами наименование печатается в первой строке, у следующих
   его документов ячейка наименования пустая и без внутренних границ (визуально объединена); группа
   строк материала не разрывается между страницами. Документ, общий для нескольких материалов, —
   отдельная строка с их перечнем (как сейчас).
5. **Норматив «В ячейку»**: переключатель «Вставлять: обозначение / с наименованием»; второй вариант —
   `СП 76.13330.2016 "Электротехнические устройства"`. Повтор определяется по обозначению. Выбор
   запоминается (в браузере панели).
6. **П.4 АОСР**: настройка на экране «Настройки» (кнопка в верхней строке) — «Исполнительная схема» перед первой схемой подряд (как
   в образце СБД, по умолчанию) или перед каждой. Хранится в настройках книги, передаётся в печать.

## 3. Книга

### 3.1 Новые поля и столбцы существующих таблиц
- «Объект»: поле «Папка сканов» (например `D:\Объект\Сканы`).
- «Организации»: «Логотип» (файл PNG/JPG — имя в папке сканов или прикреплённый).
- «Электролаборатория», «СредстваИзмерений»: «Скан».
- «Восстановить/обновить разметку» дописывает недостающие столбцы в конец существующих таблиц и
  недостающие поля «Объекта», перекрашивает правила всех таблиц по п.1–2.

### 3.2 Лист «Комплекты»
**`Комплекты`**: «№ реестра» (ключ, «1»); «Шифр» (→ Шифры; пусто — шифр первого акта комплекта);
«Том»; «Часть»; «Корпус» (`Корпус «В»`); «Перечень работ» (текст для титула); «Город» (пусто — из
«Объекта»); «Год» (пусто — год сборки); «Титул» (да/нет, по умолчанию да); «Корешки» (да/нет, да);
«Частей в томе» (число полос на корешках, по умолчанию 1).
**`АктыКомплектов`**: «Комплект» (→ Комплекты); «Акт» (→ Акты). Порядок строк = порядок актов.

### 3.3 Лист «Реестр ИД», таблица `РеестрИД`
«Комплект» (→ Комплекты); «Вид» (ВОР, АОСР, РИМ, ВД, Схема, КЖ, Протокол, Поверка, Лаборатория,
Документ качества, Прочее); «Акт» (→ Акты); «Номер документа»; «Наименование»; «Дата / период» (текст);
«Экз.» (по умолчанию 1); «Шифр чертежа»; «Скан»; «Листов» (пусто — по документу). Порядок строк
комплекта = порядок в комплекте.

### 3.4 «Заполнить из актов»
Удаляет строки комплекта и вставляет новые на место первой из них (иначе — в конец), по каждому акту
комплекта по порядку:
1. ВОР (если есть строки ВОР): «б/н», «Ведомость объемов выполненных работ», дата акта;
2. АОСР: «№<номер>.АОСР», «Акт освидетельствования скрытых работ <работы п.1>», дата акта;
3. РИМ и ВД (если есть материалы акта): «№….РИМ» «Реестр использованных материалов»; «№….ВД»
   «Ведомость смонтированного оборудования, технических средств и материалов»;
4. схемы акта: «№<номер>», «Исполнительная схема <наименование>» (вид «Прочее» — наименование как
   есть), дата схемы, скан;
5. КЖ (если есть кабели акта): «№ <шифр журнала>», «Кабельный журнал», дата журнала;
6. протокол (есть кабели и № протокола): «№<№>», «Протокол проверки сопротивления изоляции проводов,
   кабелей и обмоток электрических машин», «от <с> до <по>»;
   затем, один раз на комплект: свидетельства о поверке всех средств измерений («Свидетельство о
   поверке: <наименование> <тип>», «от <поверка> до <очередная>») и свидетельство электролаборатории
   (номер «№…» и дата «от …» берутся из текста свидетельства);
7. документы качества материалов акта в порядке РИМ, один раз на комплект: «<Тип>: <наименование для
   реестра или материалы>», дата «ДД.ММ.ГГГГ г.» / «от … до …» / «б/д», скан.
Шифр чертежа — шифр акта, «Экз.» — 1, «Листов» — пусто. Даты — «28.07.2026 г.».

## 4. Сборка комплекта

Кнопка «Собрать комплект» (в карточке строки «Комплектов» и «Реестра ИД»):
1. Панель проверяет комплект: есть акты; у строк видов ВОР…Протокол — акт из комплекта; печать
   каждого нужного документа акта проходит обычные проверки (те же сообщения, что при печати из
   карточки акта); у сканируемых видов есть «Скан» — свой или (если пусто) найденный по номеру в
   исходной таблице (схемы акта, документы качества, поверки, лаборатория).
2. Панель отправляет на сервер задание: шапку комплекта, организации, пакеты актов, строки реестра,
   логотипы, папку сканов, шаблон и настройку п.4.
3. Сервер находит файлы (ссылка `/api/files/N` — файл сервера; иначе имя в папке сканов или полный
   путь; только .pdf, .jpg, .jpeg, .png), печатает документы конструктора, считает листы, нумерует
   «л. N»/«л. N-M», печатает реестр, титул, корешки и склеивает PDF: титул → корешки → реестр →
   документы. Картинка вписывается в лист А4 (альбомный, если шире высоты).
   Ошибки файлов (нет файла, не PDF/картинка, PDF не читается или защищён) возвращаются списком
   «Реестр ИД, строка N, «Скан»: …» — комплект не собирается.
4. Предпросмотр PDF в окне, как у остальных документов; имя файла «Реестр №<№> Том <Т> Часть <Ч>.pdf».

## 5. Печать

- **Реестр**: А4 альбомный, «Страница N из M»; заголовок «РЕЕСТР ПЕРЕДАЧИ ИСПОЛНИТЕЛЬНОЙ
  ДОКУМЕНТАЦИИ №<№>.<шифр> Том №<Т>, Часть №<Ч>»; «Объект: <корпус> в составе объекта <наименование>»
  (без корпуса — наименование); «Заказчик:», «Разработчик рабочей документации:», «Подрядчик:» —
  полные реквизиты (застройщик; проектировщик шифра; подрядчик — «Выполнивший работы» первого акта, иначе
  из «Объекта», как «Велесстрой» в образце);
  «Основание для выполнения работ: Договор подряда №…» (если договор указан). Таблица 8 столбцов как в
  образце (шапка повторяется), «Листов» — заданное или фактическое, «Примечание» — «л. N»/«л. N-M».
  В конце «Сдал:» и «Принял:» с линиями «(подпись)», «(дата)».
- **Титул**: в рамке; логотипы подрядчика и заказчика; «Объект: …»; «Заказчик: <кратко>»;
  «Подрядчик: <кратко>»; «Договор строительного подряда № …» (если есть); «Исполнительная
  документация»; «Шифр РД:» шифр; «“<раздел>” <корпус>»; перечень работ; «Том № Т», «Часть № Ч»;
  «г. <город>», год.
- **Корешки**: полосы по образцу (до трёх на листе) для частей 1…N: логотипы, объект, корпус,
  «Исполнительная документация», подрядчик, «№<№>.<шифр>» «“<раздел>”», шифр, договор, «Том № Т
  Часть № i», «<год> год».

## 6. Проверка

- Тесты замечаний 1–6; генерация строк реестра на данных образца АОВ1 (строки 1–14, 16–19 образца:
  виды, номера, наименования, даты); проверки комплекта.
- Сервер: разрешение файлов (ссылка, папка, полный путь, ошибки), склейка с картинкой и PDF,
  нумерация «л.» (ВОР 3 стр. → «л. 1-3», АОСР «л. 4»), реестр/титул/корешки в тексте PDF, порядок
  страниц, лимит тела запроса комплекта 20 МБ.
- Сверка реестра, титула и корешков с образцом — скриншоты «образец | конструктор».
- Акты входного контроля не генерируются (следующий план) — пока это строки вида «Прочее» со сканом.
