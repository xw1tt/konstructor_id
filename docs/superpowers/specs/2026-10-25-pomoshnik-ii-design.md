# Этап 3: помощник-нейросеть в панели

Дата: 25.10.2026. Одобрено пользователем 25.10.2026. Источник: «Конструктор ИД: развитие продукта», раздел «Нейросеть в
панели», этап 3. Решения пользователя: локальный сервер и ключ компании (общий сервер — позже); подключения YandexGPT,
GigaChat, локальная модель, любая OpenAI-совместимая; умения — заполнение книги по тексту, проверка акта, настройка форм,
дополнение справочника.

## 1. Цель и критерий

Инженер пишет в «Помощнике» задачу словами («добавь акт на прокладку кабеля на П3 по образцу АОВ1.01.00.1, даты
10–12 ноября», «проверь акт ЭОМ-1», «сделай форму по этому файлу», «добавь вид работ монтаж СКУД»), видит предложенные
изменения «было → стало» и применяет их одной кнопкой (и отменяет одной кнопкой). Модель меняет только данные книги,
справочник и формы шаблона, через проверки программы; кода, файлов и команд у неё нет.

Три плана: 18 — подключения (сервер), 19 — инструменты, правки и чат (книга), 20 — справочник и формы. Установщик 0.18.

## 2. План 18 — подключения нейросетей

### 2.1 Настройки

`<dataDir>/ai.json`: `{ active: id | null, providers: Provider[] }`.

| Поле | Смысл |
| --- | --- |
| `id`, `name` | идентификатор, подпись |
| `kind` | `yandex` · `gigachat` · `local` · `openai` |
| `baseUrl` | адрес API. По умолчанию: yandex `https://llm.api.cloud.yandex.net/v1`, gigachat `https://gigachat.devices.sberbank.ru/api/v1`, local `http://localhost:11434/v1`, openai — обязателен |
| `model` | yandex — `gpt://<folderId>/yandexgpt/latest`, если пусто; gigachat — `GigaChat-2-Pro`; local/openai — обязательна |
| `key` | ключ API (yandex, openai), ключ авторизации (gigachat); local — необязателен |
| `folderId` | yandex: ID каталога (заголовок `OpenAI-Project`) |
| `scope` | gigachat: `GIGACHAT_API_PERS` по умолчанию (`…_B2B`, `…_CORP`) |
| `authUrl` | gigachat: `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` по умолчанию |
| `caFile` | путь к файлу корневого сертификата (gigachat — сертификат Минцифры), добавляется к системным |
| `maskNames` | не отправлять ФИО (по умолчанию: openai с адресом не localhost — да, остальные — нет) |

Ключи хранятся только в `ai.json` на ПК; API отдаёт подключения без ключа (`hasKey`). Сохранение без `key` оставляет прежний.

### 2.2 Обмен с моделью

Нейтральный формат (shared `ai/model.ts`): сообщения `system | user | assistant (text, toolCalls[{id,name,arguments}]) |
tool (toolCallId, name, content)`; инструмент — `{name, description, parameters (JSON Schema)}`; ответ —
`{message, usage {prompt, completion}}`.

- **OpenAI-совместимые (yandex, local, openai):** `POST <baseUrl>/chat/completions`, `tools` (`type: function`),
  `tool_choice: auto`; ответ `tool_calls` (аргументы — строка JSON); результат — `role: tool`, `tool_call_id`.
  Заголовки: `Authorization: Bearer <key>` (yandex — ещё `OpenAI-Project: <folderId>`).
- **GigaChat:** токен — `POST authUrl` (`Authorization: Basic <key>`, `RqUID: <uuid>`, форма `scope=…`), живёт 30 минут,
  кешируется до `expires_at − 60 с`; ответ 401 — один повтор с новым токеном. Чат — `functions`, ответ
  `finish_reason: function_call`, `message.function_call {name, arguments (объект)}`; результат — `role: function`,
  `name`, `content` — строка JSON. Один вызов функции за ход.
- HTTP — `node:https`/`node:http` с таймаутом 120 с; `caFile` — `ca: [...tls.rootCertificates, файл]`. Ошибки провайдера →
  502 с текстом «<имя подключения>: <код> <сообщение>»; нет связи/сертификат — 502 с подсказкой про сертификат для gigachat.
- Журнал расхода `<dataDir>/ai-usage.jsonl`: дата, подключение, prompt, completion. `GET /api/ai/usage` — итоги за текущий
  месяц по подключениям.

### 2.3 API

`GET /api/ai/providers` → `{active, providers (без ключей)}` · `PUT /api/ai/providers/:id` (добавить/изменить) ·
`DELETE /api/ai/providers/:id` · `PUT /api/ai/active {id}` · `POST /api/ai/providers/:id/test` (короткий запрос «Ответь
словом ОК» → `{ok, text, ms}`) · `POST /api/ai/chat {messages, tools}` → ответ активного подключения · `GET /api/ai/usage`.

## 3. План 19 — инструменты, правки, чат

### 3.1 Инструменты (shared `ai/tools.ts`, исполнение `ai/exec.ts` на данных книги)

Чтение: `list_tables` (лист, столбцы с типом и списком значений, число строк) · `read_rows {table, where?{column,
contains}, offset?, limit≤50}` (номер строки, значения по заголовкам, даты `ДД.ММ.ГГГГ`) · `check_act {act}` (ошибки
`buildBundle` + полнота по справочнику) · `get_catalog {query?}` · `get_template`.
Правки (предложения): `propose_add_rows {table, rows}` · `propose_update {table, row, values}` · `propose_delete
{table, rows}`. Предложение проверяется сразу: таблица и заголовки существуют, формульные и служебные столбцы не пишутся,
значения списков — из списка, дата `ДД.ММ.ГГГГ` → дата Excel, число с запятой → число, строка существует. Ошибка
возвращается модели текстом, чтобы она исправилась; верное — «Предложение №N будет показано пользователю».

### 3.2 Правки

`ai/changes.ts`: описание правки «было → стало» по ячейкам; применение через `TableStore`: изменения ячеек → удаления (с
конца) → добавления в конец; запись отмены (прежние значения и ссылки, удалённые строки с местами, добавленные строки);
«Отменить» — в обратном порядке. Применяются только отмеченные правки.

### 3.3 Маска ФИО

Если у подключения `maskNames`: в результатах инструментов ФИО из «Представителей» заменяются на `[ФИО-N]`; в предложениях
`[ФИО-N]` заменяются обратно. Текст пользователя не меняется.

### 3.4 Цикл и чат

Панель отправляет историю и инструменты на `/api/ai/chat`, выполняет вызовы инструментов и повторяет, пока модель не
ответит текстом (не больше 8 шагов; иначе «Помощник не уложился в 8 шагов»). Системная подсказка: что за программа,
правила (только через инструменты, правки — предложения, даты, кратко, по-русски), контекст (лист, строка, акт под
курсором, шаблон). Экран «Помощник»: сообщения, поле ввода, «Отправить», вложение файла (план 20), карточка
«Предлагаемые изменения» с галочками, «Применить»/«Отклонить», после — «Отменить»; «Новый разговор». Нет подключения —
ссылка на «Настройки». «Настройки» → «Нейросети»: подключения (добавить, изменить, удалить, сделать активным,
«Проверить»), расход за месяц.

## 4. План 20 — справочник и формы

- `propose_catalog {docs?, works?[{section, sectionName?, code, name, docs}]}`: проверка — `mergeCatalog` с дополнениями;
  применение — `PUT /api/catalog/user` с `mergeUserCatalog`; отмена — прежние дополнения. Новый `GET /api/catalog/user`.
- Форма: файл .docx/.xlsx, приложенный в чат, и акт (под курсором или названный) → существующая разметка «По образцу»
  (`POST /api/templates/:id/markup`) → `read_form` отдаёт модели: найдено меток, неоднозначные места (id, текст,
  контекст, варианты), текст документа с метками, поля с значениями акта. `propose_form {choices, replacements[{text,
  field}]}` — выбор вариантов и новые метки (`text` должен встречаться в документе, `field` — из списка полей).
  Применение — `POST /api/templates/:id/markup/:token/pairs` (метки в документе), затем «Скачать для проверки» и «Сохранить
  как форму» документа шаблона (выбор документа; встроенный шаблон — копия, как в редакторе).

## 5. Риски и проверки

1. Форматы ответов трёх видов подключений, обновление токена GigaChat по 401, ошибка провайдера — тесты на подставном
   сервере (план 18).
2. Ключ не уходит в панель; сохранение без ключа его не стирает (план 18).
3. Неверное предложение (нет столбца, формула, значение не из списка, нет строки) — не показывается, модель получает
   ошибку (план 19).
4. Применение и отмена возвращают книгу в исходное состояние (план 19).
5. Маска: ФИО не уходят в запрос, предложения с `[ФИО-N]` приходят в книгу с ФИО (план 19).
6. Справочник с повтором кода не сохраняется (план 20). Метка с неизвестным полем или отсутствующим текстом отклоняется.

Вне этапа: лимиты и списание с баланса (вместе с общим сервером), потоковый вывод ответа, голос.
