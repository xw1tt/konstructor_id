# Шаблоны пользователя и свои формы документов — дизайн

Дата: 24.10.2026. План 11 (части 1–2 большой задачи «свои шаблоны и свои акты»).

## Задача

Пользователь собирает свой шаблон: даёт ему имя, выбирает нужные документы, для каждого — встроенную форму
(по образцу СБД) или свою форму Word/Excel. Программа заполняет свои формы данными книги через метки и печатает PDF.
Шаблоны и правки пользователя, а также ширина панели сохраняются между запусками.

Следующие части (отдельные спецификации): справочник видов документов из первоисточников (приказ № 344/пр,
РД-11-02-2006, СП — только названия и обозначения), загрузка заполненных актов в книгу, PDF-бланк с полями поверх.
Перечни и бланки id-prosto.ru не переносятся (чужая подборка без разрешения).

## Решения (согласованы с пользователем)

1. Шаблон = имя + список документов; у каждого документа форма «встроенная» или «своя (.docx/.xlsx)».
2. Выбор шаблона хранится в книге (как сейчас «СБД»); сами шаблоны — на компьютере (папка данных сервера).
3. PDF своей формы: через установленный Word/Excel; если Office нет — своими силами (HTML → Edge) с предупреждением.
4. Разметка своей формы: вручную (экран «Поля для шаблона») + «Создать форму по образцу» заполненного акта.
5. Ширина панели запоминается и восстанавливается.

## 1. Модель шаблона

```ts
interface UserTemplate {
  id: string;            // "t-<uuid>"; встроенный «СБД» — "sbd"
  name: string;          // «Заказчик ПИК»
  docs: TemplateDoc[];   // порядок = порядок кнопок печати и строк реестра
}
type TemplateDoc =
  | { kind: "builtin"; doc: PrintKind }                                  // aosr, rim, vd, vor, avk, kj, ip
  | { kind: "builtin"; doc: PrintKind; form: FormRef }                   // встроенный документ по своей форме
  | { kind: "custom"; code: string; name: string; form: FormRef | null };// свой документ («АГИ», «Акт гидр. испытаний»)
interface FormRef { file: string /* имя файла в папке шаблона */; type: "docx" | "xlsx"; original: string }
```

- «СБД» — встроенный, не удаляется и не меняется; «Копия» делает из него свой шаблон.
- Код своего документа: 1–10 символов, буквы/цифры, уникален в шаблоне, не совпадает с кодами встроенных
  (АОСР, РИМ, ВД, ВОР, АВК, КЖ, ИП). Номер своего документа: `<номер акта>.<код>` (как РИМ/ВД).
- Свой документ печатается по одному на акт (кнопка в карточке акта); в реестре ИД — вид с именем документа,
  наименование = имя документа, номер = номер документа.

## 2. Хранение

- `<dataDir>/templates/<id>/template.json` + файлы форм `<dataDir>/templates/<id>/forms/<uuid>.docx|xlsx`.
- В резервную копию папки данных шаблоны попадают вместе со всем остальным.
- API сервера:
  - `GET /api/templates` → `[{ id, name, docs }]` («СБД» первым);
  - `POST /api/templates` `{ name, from?: id }` → новый (пустой или копия); `PUT /api/templates/:id` `{ name, docs }`;
    `DELETE /api/templates/:id` (кроме «sbd»);
  - `POST /api/templates/:id/forms` (тело — файл, заголовок `x-file-name`) → `FormRef`; `GET /api/templates/:id/forms/:file`;
  - `GET /api/templates/:id/export` → `<имя>.idk-template` (zip: template.json + forms/); `POST /api/templates/import`;
- Книга: настройка `idk.template` = id шаблона. Неизвестный id → предупреждение «Шаблон «…» не найден на этом
  компьютере — печать по «СБД»» и печать по «СБД».
- Ширина панели: `localStorage["idk.panelWidth"]` (обёрнуто в try/catch); при изменении размера окна панели
  (`resize`, с задержкой 500 мс) — сохранение; при запуске, если `Office.context.requirements.isSetSupported("TaskPaneApi","1.1")`,
  — `Office.extensionLifeCycle.taskpane.setWidth(w)`. Без поддержки — ничего не делаем (ширину помнит Excel).

## 3. Метки

- Синтаксис: `{Группа.Поле}`; повтор строки таблицы: `{#Список}` … `{/Список}` в одной строке таблицы Word/строке Excel —
  строка размножается по элементам списка, внутри — поля элемента `{Материал.Наименование}`.
- Словарь полей — `shared/src/forms/fields.ts`, строится из `ActBundle` теми же функциями, что встроенные формы
  (номера документов, форматы дат «05.06.2026 г.», подписи «должность ФИО»), чтобы своя форма печатала те же значения.
  Группы (первая версия):
  - `Объект`: Наименование, Адрес, Город, Договор, Дата договора, Застройщик, Строительство, Проектировщик, Шифр РД, Раздел;
  - `Акт`: Номер, Номер АОСР, Дата, Работы, Начало, Окончание, Нормативы, Разрешается, Доп. сведения, Экз., Приложения,
    Листы, Ревизия, Номер документа (для своего документа: `<номер>.<код>`);
  - роли `Технадзор`, `Строительство`, `Стройконтроль`, `Проектировщик`, `Выполнивший`, `Иные`: ФИО, Должность,
    Организация, Приказ (документ о полномочиях), НРС, Подпись (строка «должность ФИО»);
  - `АВК`: Номер, Дата;
  - списки: `Материалы` (№, Наименование, Марка, Завод, Ед., Кол-во, Документы), `Схемы` (Номер, Наименование, Дата,
    Строка п.4), `ВОР` (Участок, Материал, Ед., Объём), `Кабели` (Обозначение, Откуда, Куда, Марка, Длина).
- Неизвестная метка → в документе «[нет поля: X]», в ответе сервера — предупреждение; печать не блокируется.
- Экран панели «Поля для шаблона»: дерево групп/полей, значение на выбранном акте, кнопка «Копировать метку».

## 4. Подстановка в .docx и .xlsx

Без новых зависимостей: zip — свой (чтение уже есть, `server/src/xlsx/read.ts`; запись — новый модуль).

- **.docx** (`word/document.xml`, колонтитулы `word/header*.xml`, `word/footer*.xml`): Word режет текст на `<w:r>` —
  метка может быть разбита (`{Акт.` + `Номер}`). Перед подстановкой абзац нормализуется: тексты всех `<w:t>` абзаца
  склеиваются, метка находится в склеенном тексте, её символы переносятся в первый `<w:t>` с форматированием первого
  куска, остальные куски метки удаляются. Перевод строки в значении → `<w:br/>`. Повтор — строка `<w:tr>`,
  содержащая `{#Список}`, копируется по числу элементов.
- **.xlsx**: метки в ячейках (общие строки и inline); ячейка с одной меткой числового поля получает число. Повтор —
  строка листа с `{#Список}`: копируется, нижние строки, объединения (`mergeCell`), области печати и формулы ниже
  сдвигаются на число вставленных строк.
- Результат — заполненный файл того же формата.

## 5. PDF своей формы

- Сервер (Windows): PowerShell + COM без окна:
  - Word: `Documents.Open(path, ReadOnly)` → `ExportAsFixedFormat(out, 17)` → `Close(0)`; Excel:
    `Workbooks.Open` → `ExportAsFixedFormat(0, out)`; таймаут 60 с; процесс Office закрывается в `finally`.
  - Определение Office: успешное создание COM-объекта (кэш на время работы сервера).
- Без Office (или COM упал): своими силами — .docx → HTML (абзацы, жирный/курсив/размер, выравнивание, таблицы с
  объединением ячеек, рамки) или .xlsx → HTML-таблица; печать через Edge, как встроенные формы; предупреждение
  «Word не найден — форма может отличаться от Word».
- `POST /api/form-jobs` `{ bundle, template, doc }` → `{ id, warnings, via: "word" | "excel" | "html" }`;
  `GET /api/form-jobs/:id` (PDF), `GET /api/form-jobs/:id/source` (заполненный .docx/.xlsx). Хранение в памяти 30 мин.
- Встроенный документ без своей формы печатается как сейчас.

## 6. Разметка по образцу

«Шаблоны ▾» → «Редактор» → документ → «Создать форму по образцу»:
1. Загрузка заполненного .docx/.xlsx и выбор акта книги, по которому он заполнен.
2. Сервер ищет в тексте значения полей этого акта (`fields.ts`, значения длиной ≥ 3 символов), от длинных к коротким,
   и ставит метки. Совпадение у нескольких полей с одним значением (05.06.2026 — «Акт.Дата» и «Акт.Окончание») —
   «неоднозначно»: ответ содержит список мест с вариантами, по умолчанию — первое по приоритету (Номер > Дата акта >
   Окончание > Начало).
3. Строка таблицы, где нашёлся первый материал акта, становится строкой-повтором `Материалы` (то же для схем).
4. Панель показывает итог: «меток: N, неоднозначно: M» со списком выбора → «Сохранить форму» (или «Скачать», чтобы
   проверить в Word и загрузить обратно).

## 7. Панель

- Меню «Шаблоны ▾»: список шаблонов (выбор → в книгу), «Редактор шаблонов», «Поля для шаблона».
- Карточка акта: кнопки печати — по документам выбранного шаблона, в его порядке; для своей формы рядом
  «.docx/.xlsx» — скачать заполненный файл.
- Реестр ИД и комплект: документы шаблона по его порядку; свой документ — новый вид реестра (наименование — имя
  документа). Печать комплекта собирает и свои формы.

## 8. Тесты

- Подстановка в .docx: метка целиком, метка, разбитая на 3 `<w:r>`, перевод строки, повтор строки таблицы, колонтитул,
  неизвестная метка.
- Подстановка в .xlsx: метка в общей строке, число, повтор строки со сдвигом объединения и строк ниже.
- Словарь полей на акте АОВ1: значения совпадают со встроенными формами (номер АОСР, подписи, даты).
- Разметка по образцу: .docx, собранный в тесте из значений акта АОВ1 → метки на своих местах, неоднозначные даты.
- Хранение: создание, копия «СБД», переименование, удаление, загрузка формы, выгрузка/загрузка `.idk-template`.
- Печать без Office: HTML-путь даёт PDF с подставленными значениями и предупреждением; COM-путь — проверка
  сформированной команды PowerShell (живой Word проверяет пользователь по чек-листу README).
- Неизвестный шаблон в книге → печать по «СБД» с предупреждением.

## Вне объёма

- «Доп. поля актов» (поля, которых нет в книге) — следующий шаг.
- Справочник видов документов, импорт заполненных актов, PDF-бланки — отдельные спецификации.
- Документы «на объект» (журналы, не по акту) по своим формам.
