# Справочник видов документов и контроль полноты — дизайн

Дата: 24.10.2026. План 12 (часть 3 задачи «свои шаблоны и свои акты»).

## Задача

Пользователь собирает шаблон не вручную по одному документу, а из справочника: раздел → вид работ → документы
исполнительной документации. Программа знает, какие документы нужны каждому акту (по его виду работ), и показывает,
чего не хватает.

## Источники

- Приказ Минстроя России от 16.05.2023 № 344/пр (действует с 01.09.2023 до 01.09.2029; заменил РД-11-02-2006) —
  общий состав ИД (п. 1–13 приложения № 1): акты освидетельствования (прил. 1–5), замечания застройщика, рабочие
  чертежи с отметками, исполнительные геодезические схемы, исполнительные схемы и профили сетей, акты испытаний и
  опробования, результаты экспертиз и испытаний, документы входного контроля и качества, журналы работ.
- Документы по видам работ — по СП (только обозначение и пункт, без текста): СП 76.13330 (электротехнические
  устройства), ПУЭ гл. 1.8 (нормы приёмо-сдаточных испытаний), СП 77.13330 (системы автоматизации), СП 134.13330
  (сети связи), СП 484.1311500 (системы пожарной сигнализации). Перечни сторонних сайтов (id-prosto.ru и др.) не
  используются.

## Решения (согласованы)

1. Первая версия — профиль пользователя: электромонтаж, сети электроснабжения, слаботочные системы и сети связи,
   автоматизация (СУДИО, АСКУЭ), пожарная сигнализация.
2. Документы, которые конструктор не печатает, добавляются в шаблон как «скан» и требуют файл в реестре.
3. Контроль полноты в карточке акта и перед сборкой комплекта.
4. Документы акта определяются столбцом «Вид работ» в «Базе актов»; у акта можно снять ненужный документ.
5. Встроенный справочник (обновляется с программой) + дополнения пользователя на компьютере; встроенный документ
   можно скрыть.

## 1. Модель справочника (`shared/src/catalog/`)

```ts
interface CatalogDoc {
  code: string;            // уникальный в справочнике: «ПИК», «ПСИ», «АОСР»…
  name: string;            // «Протокол испытания кабеля повышенным напряжением»
  clause344: number;       // пункт 1–13 приложения № 1 к 344/пр
  source: string;          // «СП 76.13330.2016, п. …» / «ПУЭ, п. 1.8.40»; пусто для 344/пр как источника
  make: "builtin" | "form" | "scan"; // печатает конструктор (встроенный), своя форма, скан
  builtin?: PrintKind;     // для make=builtin
  scope: "act" | "kit";    // на акт или один раз на комплект
}
interface CatalogWork { code: string; name: string; docs: string[] /* коды документов */ }
interface CatalogSection { code: string; name: string; works: CatalogWork[] }
interface Catalog { version: string; docs: CatalogDoc[]; sections: CatalogSection[] }
```

- Встроенный справочник — данные в `shared/src/catalog/builtin.ts` (версия = дата сборки).
- Дополнения пользователя — `<dataDir>/catalog.json`: `{ docs: CatalogDoc[], sections: CatalogSection[], hidden: string[] }`
  (свои документы/разделы/виды работ, коды встроенных документов, скрытых пользователем). Итоговый справочник —
  `mergeCatalog(builtin, user)`: свои добавляются, скрытые не показываются, совпадение кода своего с встроенным —
  ошибка «Код «X» занят встроенным документом».
- API: `GET /api/catalog` (итоговый + отметка «свой»), `PUT /api/catalog/user` (дополнения целиком, с проверкой).
- Выгрузка шаблона `.idk-template` включает дополнения справочника, на которые ссылается шаблон; загрузка добавляет
  недостающие.

## 2. Шаблон и справочник

- `TemplateDoc` получает необязательные поля: `catalog?: string` (код документа справочника), `works?: string[]`
  (коды видов работ, к которым относится), `scope?: "act" | "kit"`, `scan?: boolean`.
- Встроенный документ из справочника (`make=builtin`) — `{ kind: "builtin", doc, catalog, works }`; «форма» и «скан» —
  `{ kind: "custom", code, name, form: null, catalog, works, scope, scan: make === "scan" }`.
- «Из справочника» в редакторе: дерево раздел → вид работ (галочки). Отмеченный вид работ добавляет свои документы;
  документ, который уже есть (по `catalog` или встроенному виду), не дублируется — к нему дописывается вид работ в
  `works`. Снятая галочка вида работ убирает его из `works`; документ без видов работ, добавленный из справочника,
  удаляется из шаблона (с подтверждением).
- Документ «скан»: кнопок печати нет; в реестре ИД — строка «Свой документ» с номером `<номер акта>.<код>` (на акт) или
  `<код>` (на комплект, одна строка на комплект), «Скан» заполняет пользователь; комплект требует файл, но не форму.

## 3. Книга

- «База актов»: новые столбцы (в конце) `works` «Вид работ» (ref на список видов работ — именованный диапазон из
  справочника, несколько через «; ») и `skipDocs` «Без документов» (коды документов шаблона через «; »).
- Список видов работ для проверки ввода — лист «Списки», диапазон «ВидыРабот» (обновляется при «Обновить разметку» и
  при сохранении справочника/шаблона).
- `SCHEMA_VERSION` → 8.

## 4. Документы акта и полнота (`shared/src/catalog/need.ts`)

- `actDocs(template, act)`: документы шаблона «на акт», у которых `works` пусто или пересекается с «Вид работ» акта;
  минус «Без документов». Акт без вида работ — все документы «на акт» (как сейчас).
- `kitDocs(template, acts)`: документы «на комплект», нужные хотя бы одному акту комплекта.
- `completeness(book, template, act)`: по каждому документу акта — статус:
  - «печатается» — встроенный или со своей формой;
  - «скан есть» / «нет скана» — для «скан»: строка реестра с этим номером и непустым «Сканом» (или файлом по номеру
    в папке сканов — как поиск сканов комплекта);
  - «нет формы» — свой документ «форма» без загруженной формы.
- Карточка акта: блок «Полнота» — список со значками, у каждой строки «не нужен для этого акта» (пишет код в
  «Без документов»). Сборка комплекта: перед отправкой — сводка «не хватает N документов» (ссылки на акт/строку
  реестра), предупреждение, не блокирует.

## 5. Наполнение справочника

Отдельная задача плана: для каждого раздела — виды работ и документы с пунктом 344/пр и источником (обозначение СП и
пункт, сверенные по тексту СП). Встроенные документы конструктора (АОСР, РИМ, ВД, ВОР, АВК, КЖ, протокол изоляции)
связываются с видами работ, где они нужны. Готовый справочник — таблица для просмотра пользователем до включения в
программу (исправления пользователя — до выпуска).

## 6. Тесты

- Справочник: коды уникальны; у каждого документа пункт 344/пр 1–13 и источник; ссылки видов работ на существующие
  документы; `make=builtin` ↔ `builtin` задан.
- `mergeCatalog`: свои добавляются, скрытые убираются, конфликт кода — ошибка.
- Добавление вида работ в шаблон: документы без дублей, повторный вид работ дописывается в `works`, снятие — удаление.
- `actDocs`/`kitDocs`: по виду работ, без вида работ, «Без документов».
- `completeness`: печатается / скан есть / нет скана / нет формы.
- Реестр и комплект: «скан» на акт и на комплект; комплект без файла — ошибка «Нет скана», без формы — не ошибка.
- Схема v8: новые столбцы, обновление разметки.
- API справочника: дополнения сохраняются, конфликт — 422; выгрузка/загрузка шаблона со своими документами справочника.

## Вне объёма

- Остальные разделы (земляные, бетонные, ВК, ОВ, …) — следующими выпусками по той же структуре.
- Импорт заполненных актов в книгу, PDF-бланки — отдельные спецификации.
