# Конструктор исполнительной документации (ИД): проектное описание

Дата: 15.10.2026
Статус: на согласовании у заказчика (пользователя)

## 1. Цель

Программа для подрядчика по автоматизации и диспетчеризации зданий. Она собирает
комплекты ИД по монтажу лотков, кабельных линий и оборудования из общих баз данных
и печатает их в PDF: отдельными файлами или готовым комплектом с реестром
и сквозной нумерацией листов.

Сегодня комплекты собираются вручную в Excel. Одни и те же данные (реквизиты,
представители, материалы, кабели) переписываются из документа в документ,
а сканы сертификатов подкладываются вручную. Конструктор вводит каждое значение
один раз и строит из него все документы.

### Критерии успеха

1. Контрольный комплект «Монтаж кабеля» (АОВ1.01.00, ООО «СБД»), введённый
   в конструктор, печатается в PDF, совпадающий с оригиналом по составу,
   порядку, содержанию полей и нумерации листов.
2. Повторяющиеся данные (организации, представители, материалы и их документы
   качества) вводятся один раз на объект.
3. Новый АОСР с типовым составом собирается без ручного редактирования PDF.

## 2. Рамки первой версии

**Входит:**
- один заказчик: ООО «СБД», формы по его требованиям;
- один пользователь на одном компьютере;
- документы из раздела 6.

**Не входит** (следующие версии, отдельные спецификации):
- формы других заказчиков и выбор варианта формы под заказчика;
- редактирование форм пользователем (формы встроены в программу);
- командная работа через общий сервер;
- общий журнал работ и ведомость технической документации;
- ИИ-функции.

**Заложено в архитектуре, но не реализуется сейчас:** перенос сервера на общую
машину с PostgreSQL без переписывания кода.

## 3. Исходные данные

- Образцы комплектов ИД СБД: «Монтаж лотков.pdf», «Монтаж кабеля.pdf»,
  «Монтаж оборудования.pdf».
- Рабочие Excel-файлы пользователя («Исходники АОВ1.xlsx», «0.1 Реестр ИД
  №10-АОВ.xlsx» и другие) как образец логики заполнения.
- **Актуальные формы и комплекты СБД пользователь пришлёт 16.10.2026.** Вёрстка
  печатных форм делается по ним. Если они расходятся с образцами из этого
  документа, приоритет у новых. Модель данных от этого не меняется.

## 4. Архитектура

```
 Excel (панель-надстройка)          Локальный сервер (Windows, автозапуск)
 ┌──────────────────────┐  HTTPS   ┌──────────────────────────────────────┐
 │ React + Fluent UI    │ ───────► │ Node.js + Fastify                    │
 │ Office.js            │  JSON    │  ├─ API (CRUD справочников и актов)  │
 │ вкладки 1–6          │ ◄─────── │  ├─ SQLite (файл базы) + папка сканов │
 │ большое окно:        │          │  ├─ шаблоны документов (HTML)        │
 │ предпросмотр/реестр  │          │  ├─ Chromium → PDF, pdf-lib → склейка │
 └──────────────────────┘          │  └─ проверки, резервные копии        │
                                   └──────────────────────────────────────┘
```

- **Панель в Excel.** Надстройка Office (Office.js) на TypeScript, React и Fluent UI v9.
  Всё управление идёт через вкладки. Для предпросмотра PDF и редактора реестра
  открывается большое окно (Office Dialog API).
- **Локальный сервер.** Node.js (TypeScript, Fastify) на `https://localhost:3443`.
  - База: SQLite через Drizzle ORM с миграциями. Схема пишется так, чтобы позже
    перейти на PostgreSQL.
  - Файлы: сканы и исполнительные схемы лежат в папке данных, в базе хранится
    путь и контрольная сумма.
  - Печать: HTML-шаблоны документов, Chromium (Playwright) печатает их в PDF,
    pdf-lib склеивает файлы и считает листы.
- **Общий код.** Типы и схемы проверки данных (zod) лежат в общем пакете
  и используются и сервером, и панелью.
- **HTTPS-сертификат.** При первом запуске сервер создаёт собственный корневой
  сертификат с ограничением имён (nameConstraints: только `localhost`
  и `127.0.0.1`) и ставит его в хранилище текущего пользователя. Даже при утечке
  ключа он не годится для других сайтов.
- **Связь с листами Excel.** Таблицы (кабельный журнал, материалы) можно загрузить
  в базу с активного листа и выгрузить из базы на лист.

Структура репозитория:

```
packages/
  shared/   типы, схемы zod, правила (чистые функции)
  server/   API, база, шаблоны документов, сборка PDF
  addin/    панель Excel, manifest.xml
```

## 5. Модель данных

Все сущности принадлежат объекту (`object_id`). Даты хранятся как ISO-строки.

### 5.1 Справочники объекта

**Организация**
- краткое наименование («ООО "СБД"»);
- полное наименование, ОГРН, ИНН, адрес, телефон;
- СРО: наименование, ОГРН, ИНН.
- Полная форма для АОСР собирается из этих полей.

**Объект** (один на базу в первой версии, модель допускает несколько)
- полное наименование и адрес;
- договор: номер и дата;
- город;
- роли организаций: застройщик или технический заказчик; лицо, осуществляющее
  строительство; лицо, осуществляющее подготовку проектной документации;
  лицо, выполнившее работы (по умолчанию для актов). Одна организация может
  занимать несколько ролей.

**Раздел РД**
- шифр («КУТ03-Р-ПИР-2-26-100-АОВ1.01.00»);
- наименование системы;
- организация-проектировщик.

**Представитель**
- роль АОСР: стройконтроль застройщика; лицо, осуществляющее строительство;
  его стройконтроль; проектировщик; лицо, выполнившее работы; иные;
- должность (свободный текст), ФИО;
- организация;
- документ о полномочиях: вид, номер, дата;
- номер в НРС и его дата (необязательно);
- период действия полномочий: с какой даты и по какую.
- В одной роли может быть несколько представителей одновременно
  (пример: Королёв и Востров). Порядок внутри роли задаёт пользователь.

**Материал** (общая таблица)
- наименование, марка или тип, артикул;
- производитель;
- единица измерения.

**Документ качества**
- тип: паспорт, сертификат соответствия, декларация о соответствии,
  информационное письмо, отказное письмо, прочее;
- номер, дата выдачи, срок действия (необязательно);
- число листов (определяется по скану, можно изменить вручную);
- файл скана (PDF или изображение).
- Связь «многие ко многим» с материалами.

**Средство измерения**
- наименование, тип, заводской номер, диапазон, точность;
- свидетельство о поверке: номер, даты последней и очередной поверки,
  орган поверки, скан.

**Электролаборатория**
- организация;
- свидетельство о регистрации: номер, срок действия, скан.

### 5.2 Рабочие данные

**Акт входного контроля (АВК)** — по поставке
- номер, дата, адрес;
- комиссия: представители из справочника;
- строки: материал, количество; номера документов качества подставляются
  из общей таблицы.

**Кабельная линия**
- раздел РД, группа (заголовок группы в журнале, например «Шкафы автоматики»);
- обозначение, откуда, куда;
- марка: строка и связь с материалом;
- длина по проекту;
- длины по способам прокладки: лоток, гладкая труба, гофрированная труба.
  Фактическая длина равна их сумме;
- дата прокладки;
- рабочее напряжение (для протокола).

**Значения изоляции по марке** (таблица уникальных марок кабеля объекта)
- марка;
- напряжение мегаомметра, допустимое сопротивление;
- значения по 10 парам: А-В, В-С, С-А, A-N, B-N, C-N, A-PE, B-PE, C-PE, N-PE
  (`>1000`, число или `-`).

**Протокол изоляции** (шапка)
- номер, даты замеров;
- температура, влажность, давление;
- цель испытаний, НТД;
- средства измерения, электролаборатория;
- руководитель лаборатории, кто проводил испытания.

**Барабан** (для протокола проверки на барабане)
- номер, марка, длина, завод, дата выпуска;
- состояние барабана, наружных витков, заделок;
- сопротивление, заключение.

**АОСР** (база актов)
- номер, дата, раздел РД;
- п.1: предъявленные работы (текст);
- п.2: шифр, листы, проектировщик (по умолчанию из раздела);
- п.3: материалы акта со строками «материал, количество для ВД».
  Порядок задаёт пользователь;
- п.4: документы, подтверждающие соответствие: исполнительные схемы
  (файл, номер, наименование, дата) и прочие документы (файл, тип, номер, дата);
- п.5: даты начала и окончания;
- п.6: НТД и рабочая документация (текст);
- п.7: разрешённые последующие работы;
- дополнительные сведения, число экземпляров;
- приложения: строятся автоматически, допускается ручная правка;
- лицо, выполнившее работы (по умолчанию из объекта);
- кабельные линии акта (выбор из журнала);
- ВОР: строки «наименование, ед. изм., объём, примечание», с группировкой
  по этажам;
- состав комплекта (см. 7.1).

## 6. Документы и правила заполнения

Шапки берутся из объекта, организаций и раздела. Подписи — из представителей,
полномочия которых действуют на дату документа.

| Документ | Источник данных | Правила |
|---|---|---|
| **Реестр передачи ИД** | состав комплекта | Номера и даты документов, число листов, страницы «л. X–Y» рассчитываются при сборке (7.2) |
| **ВОР** | строки ВОР акта | Группировка по этажам с подзаголовками |
| **АОСР** | акт, объект, представители | Шапка — полные реквизиты. П.3: при ≤5 материалах — список «материал — документ качества», при >5 — ссылка на РИМ. П.4: при >5 позициях — ссылка на реестр приложений. Приложения — по п.3 и п.4 |
| **РИМ** | материалы акта + документы качества | Строка на каждый документ каждого материала: тип, номер, дата, листы |
| **ВД** | материалы акта + общая таблица | Наименование, артикул, завод, ед. изм. — из таблицы; количество — из акта. Для кабеля по умолчанию предлагается сумма фактических длин линий акта этой марки |
| **Реестр приложений к АОСР** | п.4 акта | Только при >5 позициях в п.4 |
| **Исполнительные схемы** | файлы пользователя | Вставляются как есть |
| **Кабельный журнал** | линии акта | Шапка автоматическая, строки сгруппированы, фактическая длина = сумма способов прокладки |
| **Протокол изоляции** | линии акта + значения по марке + шапка протокола | Строка на каждую линию, значения подставляются по марке |
| **Протокол проверки на барабане** | барабаны | Включается, если выбран пользователем |
| **Свидетельства** (поверка, электролаборатория) | сканы | Включаются, если в комплекте есть протокол |
| **АВК** | АВК объекта | В комплект входят все АВК, где есть хотя бы один материал акта |
| **Журнал входного контроля** | все АВК объекта | Сводно, по датам; печатается отдельно от комплекта |
| **Документы качества** | сканы материалов акта | Порядок как в РИМ |

## 7. Комплект и печать

### 7.1 Состав комплекта
- По умолчанию состав строится по правилам из раздела 6 в порядке образца СБД:
  реестр, ВОР, АОСР, РИМ, ВД, схемы, КЖ, протокол, свидетельства, АВК,
  документы качества.
- Пользователь может исключить документ, поменять порядок или добавить
  произвольный PDF.
- Состав сохраняется в акте.

### 7.2 Сборка PDF
1. Каждый формируемый документ печатается в PDF, вложения берутся как есть
   (изображения переводятся в PDF A4).
2. Считается число листов каждого документа.
3. Рассчитывается нумерация «л. X–Y» и заполняется реестр. Реестр печатается
   повторно. Если от этого меняется его собственный объём, расчёт повторяется
   до стабильного результата (не более 3 проходов).
4. Результат:
   - единый PDF: `<номер АОСР>_комплект.pdf`;
   - или папка отдельных файлов: `NN_<тип>_<номер>.pdf`.

### 7.3 Предпросмотр
Любой документ комплекта можно открыть в большом окне до печати.

## 8. Вкладки панели

1. **Объект**: организации, роли, объект, разделы РД, представители.
2. **Материалы**: общая таблица и документы качества (загрузка сканов
   перетаскиванием).
3. **Входной контроль**: АВК по поставкам, журнал входного контроля.
4. **Кабели**: кабельный журнал (загрузка с листа и выгрузка на лист),
   значения изоляции по маркам, барабаны, шапка протокола.
5. **АОСР**: список актов и карточка акта по пунктам 1–7, материалы
   с количествами, кабели, схемы, ВОР.
6. **Комплект и печать**: состав, порядок, проверки, предпросмотр, печать.

Средства измерения и электролаборатория ведутся на вкладке «Кабели».

## 9. Проверки перед печатью

Проверки предупреждают, но не блокируют печать. Список выводится на вкладке 6.

- У материала нет документа качества или нет скана.
- Срок документа качества истёк на дату акта.
- У роли АОСР нет представителя с действующими полномочиями на дату акта.
- Материал акта не встречается ни в одном АВК.
- У кабельной линии нет значений изоляции для её марки.
- В акте больше 5 материалов, а РИМ исключён из комплекта.
- Дата окончания работ раньше даты начала или позже даты акта.
- Количество материала для ВД не заполнено.

## 10. Надёжность и ошибки

- Резервная копия базы и папки файлов создаётся раз в день при запуске
  сервера. Хранятся последние 30 копий.
- Если панель не может связаться с сервером, она пишет «Сервер не запущен»
  и показывает кнопку повторной попытки.
- Ошибки сборки PDF показываются с указанием документа, на котором
  они возникли. Частично собранный комплект не сохраняется.
- Все изменения в базе выполняются в транзакциях.

## 11. Тестирование

- **Модульные тесты** (shared и server) для правил:
  - сумма длин;
  - подстановка изоляции по марке;
  - пороги «>5»;
  - выбор АВК для комплекта;
  - действующие полномочия на дату;
  - расчёт нумерации листов, включая повторный проход реестра.
- **Интеграционные тесты API** на временной базе SQLite.
- **Контрольный пример.** Данные комплекта «Монтаж кабеля» (АОВ1.01.00)
  вводятся сидом. Собранный PDF сверяется с оригиналом:
  - автоматически: состав, число листов, ключевые поля в тексте;
  - вручную: визуально.

## 12. Порядок разработки

1. Каркас: сервер, база, миграции, сертификат, пустая надстройка, связь
   «панель ↔ сервер».
2. Вкладка «Объект» с организациями, ролями и представителями.
3. Материалы и документы качества со сканами.
4. АОСР: карточка акта; печать АОСР в PDF.
5. РИМ, ВД, реестр приложений, ВОР.
6. Кабели: журнал, изоляция, протоколы, свидетельства.
7. Входной контроль: АВК и журнал.
8. Комплект: состав, нумерация, сборка PDF, проверки, предпросмотр.
9. Контрольный пример и сверка с оригиналом.

Шаги 4–7 зависят от актуальных форм СБД (раздел 3).
