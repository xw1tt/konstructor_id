# Протоколы испытаний и акты приёмки: встроенная печать 16 документов справочника

Дата: 25.10.2026. Статус: решения приняты по указаниям пользователя (25.10.2026); пересматриваются по замечаниям.

## 1. Цель

В справочнике документов (план 12) 16 документов не печатаются конструктором: 8 «своя форма» (без формы — «нет формы»
в полноте) и 8 «скан» (протоколы электролаборатории). Нужно, чтобы конструктор печатал все 16 по данным книги, как сейчас
ПСИ и КЖ, и чтобы любую из этих форм можно было выгрузить в Word с метками и поправить под себя.

Решения пользователя: делаются все 16 (вариант 2); вид — встроенная печать плюс выгрузка .docx с метками (вариант 3);
четыре этапа подряд без остановок: 1) протоколы лаборатории + выгрузка .docx; 2) кабели и трубы; 3) акты приёмки;
4) слаботочка.

Образцов форм у пользователя нет: формы составлены по содержанию приложений СП 76.13330.2016, СП 77.13330.2016 и пунктов
ПУЭ гл. 1.8 (обязательные сведения: кто, что, когда, чем, по какому нормативу, результат, заключение, подписи). Это не копия
бланков; пришедший позже образец загружается как своя форма («По образцу» или .docx с метками).

### Критерии успеха

1. Каждый из 16 документов печатается из книги в PDF кнопкой (в карточке акта — документы «на акт», в карточке комплекта —
   «на комплект»), попадает в реестр ИД и в собранный комплект с номерами листов.
2. Перед печатью — проверка как у остальных документов: список «лист, строка, столбец» с переходом к ячейке.
3. Результат строки замера, который можно вычислить из чисел (время срабатывания, сопротивление, затухание…), считается
   сам; результат, который вычислить нельзя, вносится и обязателен. Заключение по умолчанию не печатается, если хоть одна
   строка «не соответствует».
4. «Образец .docx» любого из 16 документов открывается в Word, содержит метки и строку-повтор; загруженный как форма
   документа шаблона — печатает те же данные.
5. Книга v8 → «Обновить разметку» → новые листы и таблицы; прежние данные и шаблоны работают как раньше.

## 2. Рамки

Входит: 16 документов (таблица §4), таблицы книги для их данных, проверка, печать PDF, реестр/комплект, полнота,
образец .docx, перевод справочника и шаблонов плана 12 на встроенную печать этих документов.

Не входит: импорт файлов тестеров (Fluke и т. п.) — отдельная задача; ОЖР раздел 5 (новые документы туда не попадают,
как и раньше); автоподбор строк замеров из кабельного журнала, кроме «Собрать линии» (§5.4).

## 3. Архитектура: один движок по описанию документа

Вместо 16 шаблонов — описание документа (`ProtoDef`) и общий движок:

```
shared/protocols/defs.ts     ProtoDef для 16 кодов: заголовок, «на акт/комплект», подписи (лаборатория или комиссия),
                             таблица книги со строками, столбцы печати, правило результата, нормативы по умолчанию.
shared/protocols/bundle.ts   buildProtoBundle(book, номер документа) → ActBundle + proto (данные документа) | ошибки.
shared/protocols/find.ts     поиск строки «Протоколы» для акта/комплекта; номер документа для реестра и полноты.
server/print/templates/proto.ts   HTML: «протокол лаборатории» (альбомный) или «акт комиссии» (книжный).
server/forms/protoDocx.ts    образец .docx с метками из того же описания.
```

ActBundle получает необязательное поле `proto` (как `cables`): печать, свои формы (FormData) и комплект берут данные
документа из пакета. Документ «на комплект» несёт пакет первого акта комплекта (объект, организации, представители).

### 3.1. Виды печати

`PRINT_KINDS` дополняется `PROTO_KINDS` (латиница, как прочие): pkl, pav, puzo, pfn, pms, pzu, pokb, ppkb, atp, aii, atg,
apnr, aoma, arps, pzov, ptsks. Подписи (`BUILTIN_DOC_LABELS`) — коды справочника (ПКЛ, ПАВ…). Код и вид связаны в
`PROTO_DEFS` — единственном источнике.

### 3.2. Справочник и шаблоны

В справочнике 16 документов получают `make: "builtin"` и `builtin: <вид>`. «Из справочника» добавляет их в шаблон как
встроенные. Шаблоны, сохранённые планом 12 (свой документ с `catalog` = код из 16, без формы или «скан»), при чтении
переводятся во встроенный документ (`upgradeTemplate`): виды работ сохраняются, загруженная своя форма — тоже (становится
формой встроенного документа). Область «на акт / на комплект» встроенного документа берётся из `PROTO_DEFS`.

## 6. Печать

### 6.1. Протокол лаборатории (альбомный A4, как ПСИ)

Шапка (лаборатория и свидетельство | заказчик, объект, шифр, даты); «Протокол №N»; наименование документа; климатические
условия (кроме ПЗОВ/ПТСКС: только температура); цель; нормативы; «Предмет»; таблица результатов с номерами граф,
шапка повторяется на страницах; заключение; перечень средств измерений (как ПСИ); подписи «Руководитель
электролаборатории», «Испытания провёл».

### 6.2. Акт комиссии (книжный A4)

«АКТ №N» и наименование; «г. <город объекта>» и дата; объект; «Комиссия в составе:» — по роли строка «<роль>: <должность>
<организация> <ФИО>»; вводный текст документа («произвела … и установила:»); таблица строк; заключение; нормативы;
подписи членов комиссии. Роли: ПОКБ, ППКБ — стройконтроль подрядчика, выполнивший работы; АТП, АОМА, АПНР — технадзор
застройщика, лицо, осуществляющее строительство, выполнивший работы; АИИ, АТГ, АРПС — те же и проектировщик (если есть).
Нет ни одного представителя ролей документа — ошибка проверки «Представители: нет членов комиссии для <код>».

### 6.3. Результаты и заключение

Правило результата (`result(row)`) — у вида документа: ПАВ — факт ≤ верхней границы нормы; ПУЗО — 0,5·IΔн ≤ факт ≤ IΔн
и время ≤ нормы; ПФН — Iкз ≥ Iсрабатывания; ПМС, ПЗУ — сопротивление (ПЗУ — × сезонный коэффициент) ≤ допустимого;
ПЗОВ — затухание ≤ нормы; ПТСКС — разводка PASS, запасы ≥ 0. Внесённый «Результат» печатается как есть; пусто и
вычислить нельзя — ошибка «Не заполнено». Печатается «соответствует» / «не соответствует».

Заключение по умолчанию — у документа («Результаты измерений соответствуют требованиям <нормативы>» и т. п.). Если в
строках есть «не соответствует», а «Заключение» пусто — ошибка проверки «Есть строки «не соответствует» — впишите
заключение».

### 6.4. Номер, имя файла, реестр, комплект, полнота

- Номер — «№ документа» шапки; файл — «<код> №<номер>.pdf».
- Реестр ИД: новый вид строки «Акт/протокол»; «Заполнить из актов» добавляет строку документа (номер «№<номер>»,
  наименование, дата или период) после КЖ/протокола акта (на акт) или в конце блока комплекта (на комплект). Нет шапки —
  строки нет, полнота показывает «нет данных».
- Сборка комплекта: строка «Акт/протокол» находит шапку по номеру, собирает пакет и печатает.
- Полнота: статус «нет данных: <документ>» (`noData`) — нет строки «Протоколы» для акта/комплекта; считается в «Не хватает
  документов».

## 7. Образец .docx

`GET /api/forms/sample/<вид>` — .docx с метками: `{Документ.Номер}`, `{Документ.Дата}`, `{Документ.Предмет}`…,
`{Объект.Наименование}`, строка-повтор таблицы `{#Строки}{Строка.<заголовок>}…{/Строки}`, `{#Комиссия}…{/Комиссия}`,
`{#Приборы}…{/Приборы}`. Значения этих меток FormData строит из `bundle.proto` (`protoFormData`). В редакторе шаблонов у
встроенного документа из 16 — ссылка «Образец .docx».

## 8. Ошибки и совместимость

- Книга без новых листов — печать документа: «В книге нет таблицы «Протоколы» — «Обновить разметку»».
- Повтор «№ документа» — ошибка, как у других ключей.
- Документ «на акт» с пустым «Акт» или «на комплект» без комплекта и акта — ошибка строки шапки.
- Шаблоны плана 12 — `upgradeTemplate` при чтении; формы пользователя сохраняются.

## 9. Тесты

На каждый этап: схема и разметка v9 (новые таблицы в конце, данные не трогаются); проверка (ошибки с текстами §6–8);
правила результата (граница «равно», пустые значения); HTML печати (номер, строки, подписи, перенос шапки таблицы); PDF
одного документа каждого этапа через браузер; реестр и комплект с документом «на акт» и «на комплект»; полнота `noData`;
образец .docx → загрузка как форма → печать даёт значения; `upgradeTemplate` шаблона плана 12.
