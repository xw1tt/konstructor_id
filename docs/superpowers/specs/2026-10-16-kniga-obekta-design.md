# Книга объекта: листы Excel как хранилище, новая панель

Дата: 16.10.2026
Заменяет в основной спецификации (`2026-10-15-konstruktor-id-design.md`) раздел о хранении данных:
реквизиты, представители, материалы, документы качества и акты теперь хранятся **в книге Excel**,
а не в базе на сервере. Формы печати (`2026-10-16-formy-sbd-addendum.md`) не меняются.
Прототип книги: `docs/prototype/kniga-obekta.xlsx` (данные акта К32.В.СТ.АОВ1.01.00.1).

## 1. Цель

Пользователь работает в Excel. Каждому разделу панели соответствует лист книги. Правка в панели
сразу видна на листе, правка на листе — сразу в панели. Книгу можно скопировать, переслать и
открыть без программы. Сервер хранит только сканы и печатает PDF.

## 2. Решения, принятые при обсуждении

| Вопрос | Решение |
|---|---|
| Где основные данные | В книге Excel (одна книга — один объект) |
| Материалы и документы качества | Два листа; документ ссылается на один или несколько материалов |
| Акты | Лист «База актов» + листы «Исполнительные схемы», «Материалы в актах», «ВОР» |
| Кабельный журнал | Форма СБД + служебные столбцы «Акт» и «Группа» |
| Важные столбцы | Отмечаются галочками; пустые ячейки подсвечиваются; проверка перед печатью |
| Существующие данные в базе | Переносятся в книгу кнопкой «Создать книгу объекта» |
| Связь панели и листов | «Умные таблицы» Excel + события Excel (без копии данных в панели) |

## 3. Листы и таблицы

Каждая таблица — «умная таблица» Excel с постоянным именем. Заголовки — точно как ниже.
Служебные столбцы (в бланк не печатаются) помечены «служ.».

### 3.1. «Реквизиты»

**`Объект`** — вертикальная таблица «Поле | Значение». Поля (в этом порядке):
Наименование объекта; Адрес; Город; Договор №; Дата договора; Застройщик (технический заказчик);
Лицо, осуществляющее строительство; Лицо, осуществляющее подготовку проектной документации;
Лицо, выполнившее работы (по умолчанию). Последние четыре — ссылка на `Организации`.

**`Организации`**: Краткое наименование (ключ); Полное наименование; ОГРН; ИНН; Адрес; Телефон;
СРО: наименование; СРО: ОГРН; СРО: ИНН.

**`Шифры`**: Шифр (ключ); Наименование раздела; Проектировщик (→ Организации).

### 3.2. «Представители» — `Представители`

Роль (список из шести подписей ниже); Должность; ФИО (ключ); Организация (→ Организации);
Документ о полномочиях; НРС №; Дата НРС; Действует с; Действует по; Порядок; Текст для акта.

Подписи ролей в книге → коды программы:

| В книге | Код |
|---|---|
| Технадзор застройщика | developer_control |
| Лицо, осуществляющее строительство | builder |
| Строительный контроль подрядчика | builder_control |
| Проектировщик | designer |
| Выполнивший работы | performer |
| Иные представители | other |

### 3.3. «Материалы» — `Материалы`

Наименование (ключ); Марка; Артикул; Завод-изготовитель; Ед. изм.

### 3.4. «Документы качества» — `ДокументыКачества`

Материалы (одно или несколько наименований через «; »); Тип (Паспорт качества / Сертификат
соответствия / Декларация о соответствии / Информационное письмо / Отказное письмо / Прочее);
Номер; Дата; Действует до; Листов; Наименование для реестра; Скан (служ.).

### 3.5. «База актов» — `Акты`

Номер акта (ключ); Дата акта; Шифр (→ Шифры); Работы (п.1); Листы; Ревизия; Начало работ;
Окончание работ; Нормативы (п.6); Разрешается (п.7); Доп. сведения (по умолчанию «нет»);
Экз. (по умолчанию 4); Приложения (по умолчанию «Согласно п.3, п.4.»); Выполнивший работы
(→ Организации); Заголовок ВОР; ВОР: от заказчика (→ Представители); ВОР: от монтажников
(→ Представители).

Значения по умолчанию для новой строки акта — как в дополнении о формах СБД (§2, §5): номер —
следующий по числовому суффиксу, подписанты ВОР — первый developer_control и последний performer.

### 3.6. «Исполнительные схемы» — `Схемы`

Акт (→ Акты); Вид (Схема / Прочее); Номер; Наименование; Дата; Скан (служ.).

### 3.7. «Материалы в актах» — `МатериалыАктов`

Акт (→ Акты); Материал (→ Материалы); № поз. по УСР (по умолчанию «б/н»); Кол-во;
Сумма ВОР (служ., формула `SUMIFS` по листу «ВОР»). Пустое «Кол-во» — в ВД идёт «Сумма ВОР».
Порядок строк акта на листе = порядок материалов в акте.

### 3.8. «ВОР» — `ВОР`

Акт (→ Акты); Этаж / участок; Материал (→ Материалы; должен быть в «Материалах в актах» этого акта);
Объём.

### 3.9. «Кабельный журнал» — `КабельныйЖурнал`

Акт (служ., → Акты); Группа (служ.); Обозначение кабеля, жгута, трубы (ключ); Откуда; Куда;
Направление по планам расположения; Кабель: марка, число жил, сечение; Кабель: длина, м;
Труба: марка, диаметр; Труба: длина, м; Примечание.
Печать журнала и протокол изоляции — в следующих планах; сейчас — только лист и раздел панели.

### 3.10. Общие правила

- **Ключи** уникальны внутри таблицы. Повторы подсвечиваются жёлтым (условное форматирование).
  Ссылки между листами идут по значению ключа.
- **Ссылки** — выпадающие списки Excel на столбец целевой таблицы
  (`=INDIRECT("Материалы[Наименование]")`). Столбец «Материалы» в документах качества допускает
  несколько значений через «; », поэтому проверка списка там не запрещает ввод.
- **Даты** хранятся как даты Excel, формат `ДД.ММ.ГГГГ`; **числа** — как числа.
- **Важные столбцы** по умолчанию — красные заголовки в прототипе. Пустая ячейка важного столбца
  в непустой строке подсвечивается розовым. Пользователь может отметить и снять столбцы.
- **Служебные настройки** (версия разметки, отметки важных столбцов) хранятся в настройках
  документа Office (`Office.context.document.settings`) и сохраняются вместе с файлом.

## 4. Панель

```
┌ Конструктор ИД ─────────────────────┐
│ [Реквизиты][Представители][Акты]    │  ← разделы
│ [Материалы][Схемы][Кабельный журнал]│
├ Функционал листа: «Материалы» ──────┤
│ [+1] [+10] [Дублировать] [↑] [↓]    │
│ [Удалить] [Важные столбцы]          │
├ Функционал таблицы: «Материалы» ▾ ──┤
│ ● Наименование  ● Завод  ● Ед.изм.  │
│   Марка   Артикул                   │
├ Строка 7 ───────────────────────────┤
│ карточка текущей строки             │
└─────────────────────────────────────┘
```

### 4.1. Разделы

| Раздел | Листы |
|---|---|
| Реквизиты | Реквизиты |
| Представители | Представители |
| Акты | База актов; переходы на «Исполнительные схемы», «Материалы в актах», «ВОР» |
| Материалы | Материалы; переключатель на «Документы качества» |
| Схемы | Исполнительные схемы |
| Кабельный журнал | Кабельный журнал |

- Клик по разделу активирует его лист; смена листа в Excel переключает раздел.
- Лист без таблиц программы — разделы неактивны, «Функционал листа» работает с обычными строками
  листа, карточки нет.
- Если в книге нет таблиц программы — вместо разделов кнопка «Создать книгу объекта» (§6).

### 4.2. Функционал листа

Работает на активном листе.

| Кнопка | Курсор в таблице | Курсор вне таблицы |
|---|---|---|
| +1 / +10 | строки под текущей строкой таблицы | строки листа под текущей |
| Дублировать | копия текущей строки под ней | копия строки листа под ней |
| ↑ / ↓ | обмен значениями с соседней строкой таблицы, курсор следует за строкой; у края — ничего | обмен с соседней строкой листа |
| Удалить | выделенные строки таблицы (все, если выделено несколько) | выделенные строки листа |
| Важные столбцы | список столбцов текущей таблицы с галочками | неактивна |

- **Удалить** спрашивает подтверждение с числом строк. Если на удаляемые ключи ссылаются строки
  других листов — в подтверждении сказано, сколько и где.
- Формулы в служебных столбцах (Сумма ВОР) при вставке, дублировании и перестановке не
  затираются: программа переносит только значения не-формульных столбцов.

### 4.3. Функционал таблицы

- Показывает столбцы таблицы под курсором. Если курсор вне таблицы, а на листе таблиц несколько
  (Реквизиты) — выпадающий список таблиц; по умолчанию первая.
- Важные столбцы — с точкой; точка красная, если ячейка текущей строки пуста.
- Клик по столбцу выделяет его ячейку в текущей строке (вне таблицы — в первой строке данных).

### 4.4. Карточка текущей строки

Поля строки по описанию схемы: текст, многострочный текст (п.1, п.6, п.7), дата (календарь),
число (десятичная запятая), список, ссылка (выпадающий список ключей целевой таблицы), несколько
ссылок (галочки — «Материалы» в документе качества), скан (загрузка на сервер, в ячейку —
гиперссылка «имя файла»).

Дополнения:
- **Материал:** список его документов качества (строки «Документов качества», где он упомянут),
  кнопка «Добавить документ» — новая строка в «Документах качества» с этим материалом, переход
  к ней.
- **Акт:** сводка «схем N, материалов N, строк ВОР N» с кнопками перехода (лист активируется,
  автофильтр по номеру акта); проверка перед печатью; кнопки печати АОСР, РИМ, ВД, ВОР
  (предпросмотр — как сейчас).
- **Кабельный журнал:** сумма длин кабеля по акту текущей строки.

### 4.5. Синхронизация

- Панель не хранит копию данных: при смене выделения или изменении таблицы перечитывает
  текущую таблицу (события `onSelectionChanged`, `onChanged` листа/таблицы).
- Правка поля карточки пишется в ячейку при уходе из поля (blur) или выборе значения из списка.
- Пока поле в фокусе, внешнее изменение той же ячейки не перетирает ввод; после выхода из поля
  побеждает последнее записанное значение.
- **Переименование ключа.** Изменение ключа (в карточке или в ячейке) — программа ищет ссылки
  на старое значение и предлагает «Обновить ссылки: 5 строк на 2 листах». В ячейке старое
  значение берётся из события изменения; при вставке диапазоном (много ячеек) переименование
  не распознаётся, ссылки не трогаются, проверка покажет висячие ссылки.

## 5. Печать

1. Панель по номеру акта собирает **пакет акта** из книги: объект, организации (полные данные
   всех, на кого ссылаются), шифр, представители (с кодами ролей), акт, материалы акта с их
   документами качества, схемы, строки ВОР.
2. **Проверка пакета:** важные поля, висячие ссылки, материалы ВОР вне «Материалов в актах»,
   некорректные даты и числа. Есть ошибки — список «лист, строка, столбец: что не так»,
   печать не идёт.
3. Пакет уходит на сервер `POST /api/print/:doc` (doc = aosr | rim | vd | vor), сервер возвращает
   PDF. Предпросмотр: панель отправляет пакет `POST /api/print-jobs`, получает id, окно
   предпросмотра открывает `GET /api/print-jobs/:id/:doc` (задания живут 30 минут в памяти).
4. Шаблоны и правила (`rows.ts`, `repLine.ts`, `templates/*`) не меняются. Сервер превращает
   пакет в ту же структуру данных, что сейчас строит из базы `print/data.ts`.

Критерий: пакет, собранный из прототипа книги, даёт PDF с тем же текстом, что сейчас даёт
`npm run seed:sbd` из базы.

## 6. Создание книги и перенос данных

**«Создать книгу объекта»** (в книге нет таблиц программы):
1. Создаёт недостающие листы и таблицы по схеме, оформление и проверки как в прототипе.
2. Если на сервере в базе есть данные (`GET /api/export` не пуст) — предлагает перенести:
   организации, объект, шифры, представители, материалы, документы качества, акты со схемами,
   материалами и ВОР. Сканы остаются на сервере, в книгу пишутся гиперссылки.
3. Записывает версию разметки в настройки документа.

После перехода вкладки «Объект», «Материалы», «АОСР» и их маршруты API удаляются из панели;
таблицы базы на сервере остаются нетронутыми (откат), но программой не используются. Таблица
файлов (сканы) и маршруты `/api/files` остаются.

Если таблица программы удалена или переименована пользователем — раздел показывает «Таблица
не найдена» и кнопку «Восстановить разметку» (создаёт недостающее, данные не трогает).

## 7. Устройство кода

- **`@idk/shared/workbook/schema.ts`** — описание листов/таблиц/столбцов: заголовок, тип, ключ,
  ссылка, важный по умолчанию, служебный, значение по умолчанию. Единственный источник.
- **`@idk/shared/workbook/*`** — чистая логика без Office.js:
  преобразование строк ↔ записи; операции над строками (вставка, дублирование, обмен, удаление);
  поиск ссылок и переименование ключей; проверка; сборка пакета акта; перенос из экспорта базы.
  Работает через интерфейс `WorkbookPort`.
- **`@idk/addin/excel/port.ts`** — реализация `WorkbookPort` на Office.js (тонкий слой).
- **`@idk/addin` тестовая модель** — `MemoryWorkbook` реализует `WorkbookPort` в памяти;
  на ней тесты логики.
- **Сервер:** `POST /api/print/:doc`, `/api/print-jobs`, `GET /api/export`; `print/data.ts`
  получает функцию «пакет → данные шаблонов».

## 8. Ограничения и ошибки

- Требуется Excel 2019 / 2021 / 365 (ExcelApi 1.9). На более старом — сообщение в панели.
- Текст в числовом или дате-столбце — ошибка поля в карточке и в проверке перед печатью.
- Сервер недоступен — работа с листами продолжается, недоступны печать и сканы.

## 9. Проверка

- Автотесты (node:test) на всю логику `workbook/*` через `MemoryWorkbook`.
- Тест сервера: пакет из прототипа → PDF, текст совпадает с печатью из базы.
- Ручная проверка пользователем в Excel по списку сценариев (README).

## 10. Вне рамок этого плана

Печать кабельного журнала и протокола изоляции, реестр ИД и сборка комплекта, акты входного
контроля, командная работа, ИИ-ассистент.
