# Этап 1, часть 1: облачный сервер — учётные записи, баланс, консоль владельца, вход в панели

Дата: 25.10.2026. Черновик на согласование. Решения пользователя: сервер — сразу в облаке в РФ (Yandex Cloud / Selectel);
баланс в рублях с начала (абонентская плата за рабочие места + расход нейросети), пополнение вручную владельцем;
выдача, продление, приостановка и списание — только у владельца сервиса.

## 1. Цель и границы

Часть 1 даёт: облачный сервер с базой PostgreSQL, компании и пользователей, вход в панели Excel, консоль владельца в
браузере, баланс с журналом операций и ежедневным списанием, статус доступа в панели. Книги объектов **пока остаются в
Excel** (часть 2 перенесёт их на сервер), печать и сканы — на локальном сервере ПК, как сейчас. Нейросеть подписки и
библиотека на сервере — часть 3.

Без облака (адрес сервера не задан) панель работает как в 0.19 — ничего не ломается у текущих пользователей.

## 2. Устройство

```
Excel + панель ──https──► облачный сервер (Node) ──► PostgreSQL
      │                         └── консоль владельца и администратора компании (браузер, /console)
      └──https──► локальный сервер ПК (печать PDF, сканы, шаблоны) — без изменений
```

- Новый пакет `packages/cloud`: тот же HTTP-роутер, что у локального сервера; доступ к базе — тонкий интерфейс
  `Db.query(sql, params)` с двумя реализациями: `pg` (PostgreSQL в облаке) и PGlite (PostgreSQL в WebAssembly) — для
  автотестов и локального запуска без установки PostgreSQL. Миграции — SQL-файлы по порядку.
- Консоль — React-страница `/console` того же сервера.
- Развёртывание: Docker Compose (сервер, PostgreSQL, Caddy с бесплатным сертификатом HTTPS Let's Encrypt), скрипт
  установки на чистую Ubuntu-ВМ, ежедневная резервная копия базы. Нужен домен (например, `id.<ваш-домен>.ru`).

## 3. Данные

| Таблица | Поля (главное) |
| --- | --- |
| `tenants` — компании | название, ИНН, статус (`active` / `suspended`), число рабочих мест, тариф, кредитный лимит (₽, по умолчанию 0) |
| `users` | компания (у владельца сервиса — нет), почта (уникальна), имя, роль, хеш пароля (scrypt), статус (`active` / `blocked`) |
| `invites` | ссылка-приглашение: компания, почта, роль, срок 7 дней |
| `sessions` | хеш токена, пользователь, где вход (панель / консоль), срок 30 дней, последнее обращение |
| `tariffs` | название, ₽ за рабочее место в месяц, ₽ за 1000 токенов нейросети, проверяющие бесплатно (да/нет) |
| `ledger` — операции баланса | компания, время, вид (`topup` пополнение, `fee` абонентская плата, `ai` нейросеть, `adjust` корректировка), сумма ₽ (+/−), автор, причина |
| `audit` | время, кто, действие, над чем, подробности — все действия владельца и администраторов |

Роли: **владелец сервиса** (вы: всё по всем компаниям), **администратор компании** (приглашает и блокирует своих
сотрудников, видит баланс и операции — менять баланс не может), **инженер** (работает в панели), **проверяющий**
(технадзор, стройконтроль: только чтение; рабочее место по тарифу бесплатно).

Баланс = сумма операций. Списание абонентской платы — раз в сутки (00:05 МСК): `места × цена / дней в месяце`, одна операция
на компанию и день (повторный запуск не списывает дважды). Доступ компании:
- **активен** — статус `active` и баланс > −кредитный лимит;
- **только чтение** — баланс исчерпан: панель работает с книгой и выгрузкой, печать, комплект и помощник недоступны,
  в панели — «Пополните баланс»;
- **приостановлен** — владелец приостановил: то же, с текстом «Доступ приостановлен».

## 4. Сервер: API

- `POST /api/auth/login` (почта, пароль → токен; 5 неудачных попыток за 10 минут — пауза) · `POST /api/auth/logout` ·
  `GET /api/me` (пользователь, компания, доступ, баланс, тариф) · `POST /api/auth/password` (смена пароля) ·
  `GET/POST /api/invites/:token` (принять приглашение: имя, пароль).
- Владелец: компании (создать, изменить, места, тариф, кредитный лимит, приостановить/возобновить), пополнение и
  корректировка баланса (сумма и причина обязательны), тарифы, пользователи любой компании (пригласить, заблокировать,
  сбросить пароль ссылкой), операции и журнал действий с отбором.
- Администратор компании: сотрудники (пригласить, заблокировать, роль в пределах числа мест), операции баланса.
- Защита: токен — 32 случайных байта, в базе — хеш; CORS только для адреса панели (`https://localhost:3443`) и консоли;
  все изменения — в `audit`.

## 5. Панель

- «Настройки» → «Облако»: адрес сервера (пусто — работа без облака, как сейчас).
- Задан адрес — при запуске экран «Вход» (почта, пароль). Токен хранится на этом ПК; «Выйти» — в «Настройках».
- В верхней строке — компания и баланс; при «только чтение» / «приостановлен» — плашка с причиной, кнопки печати,
  комплекта, помощника недоступны (подсказка «Пополните баланс» / «Доступ приостановлен владельцем сервиса»).
- Проверка доступа — при запуске и раз в 10 минут; нет связи с облаком — работа продолжается 24 часа по последнему
  известному статусу (чтобы обрыв интернета на объекте не останавливал работу).

## 6. Консоль (браузер)

Владелец: «Компании» (список: баланс, места, доступ; карточка — пользователи, операции, кнопки «Пополнить»,
«Корректировка», «Приостановить», места, тариф), «Тарифы», «Журнал действий». Администратор компании: «Сотрудники»
(пригласить по почте — ссылка показывается для отправки), «Баланс и операции». Первый владелец создаётся командой на
сервере при установке.

## 8. Риски и проверки

1. Данные одной компании не видны другой — тесты на каждый маршрут с чужим токеном.
2. Ежедневное списание не дублируется при повторном запуске и перезапуске сервера — тест.
3. Обрыв связи не останавливает работу в панели 24 часа — тест.
4. Пароли — только хеши; токен в базе — только хеш; вход с перебором паролей тормозится — тесты.
5. Без адреса облака панель работает как 0.19 — весь прежний набор тестов.

Вне части 1: книги на сервере (часть 2), нейросеть и библиотека через сервер (часть 3), оплата картой и счета через ЭДО
(этап 2), вход через корпоративный каталог.
