# Спецификация проекта и учёт закрытых объёмов (РКЦ) — дизайн

Дата: 19.10.2026. План 10.

## Задача

В конструкторе нужно видеть по каждой позиции проекта: сколько всего по проекту, сколько закрыто в каждом акте,
сколько закрыто всего и сколько осталось. Источник позиций — расчёт коммерческой стоимости (РКЦ, файл Excel заказчика)
или таблица, составленная вручную. Доп. позиции добавляются строками.

Сейчас этот учёт ведётся вручную на листе «ИД» в РКЦ (столбцы «Остаток», «Всего заактировано», пара к-во/сумма на акт).

## Решения (согласованы с пользователем)

1. Связь материала с позицией — по №п/п РКЦ: в справочнике «Материалы» столбец «№ п/п РКЦ», заполняется вручную
   (для исключения ошибок); столбец обычный, редактируемый — его может заполнить и ИИ.
2. Подбор №п/п — и кнопкой в панели (по сходству наименований), и вручную/ИИ.
3. Работы и услуги из РКЦ тоже попадают в спецификацию.
4. Повторная загрузка РКЦ — обновление по №п/п, ничего не теряется.
5. Разбивка по актам — и отдельным листом, и на карточке позиции.
6. Цены и суммы не переносятся — учёт только количеств.

## 1. Данные книги

### Таблица «Спецификация» (лист «Спецификация»)

| Ключ | Заголовок | Тип | Примечание |
|---|---|---|---|
| number | № п/п | text, ключ, важный | номер из РКЦ как текст («1.1.2.3», «2.1.1.»); у позиций без номера — «б/н-1», «б/н-2»… |
| section | Раздел | text | заголовок ближайшей группы РКЦ, например «КАБЕЛИ И ПРОВОДА» |
| name | Наименование | longtext, важный | |
| unit | Ед. изм. | text | |
| quantity | Кол-во по проекту | number, важный | |
| closed | Закрыто | formula, служебный | `=SUMIFS(МатериалыАктов[Учёт],МатериалыАктов[№ п/п РКЦ],[@[№ п/п]])` |
| rest | Остаток | formula, служебный | `=[@[Кол-во по проекту]]-[@Закрыто]`; отрицательный — красная заливка (условное форматирование) |
| source | Источник | enum «РКЦ» / «вручную», по умолчанию «вручную» | |
| note | Примечание | text | при повторной загрузке сюда пишется «нет в РКЦ (д.с.…)» |

Строки разделов отдельными строками таблицы не хранятся: заголовок группы — значение столбца «Раздел» у каждой позиции.

Столбец «№ п/п» форматируется как текст, чтобы Excel не превращал «1.1» в число или дату.

### Новые столбцы в существующих таблицах

- «Материалы»: `rkc` «№ п/п РКЦ» — ref на «Спецификация» (выпадающий список номеров), не обязательный.
- «МатериалыАктов» (служебные формулы, в конце таблицы):
  - `rkc` «№ п/п РКЦ» = `=IFERROR(INDEX(Материалы[№ п/п РКЦ],MATCH([@Материал],Материалы[Наименование],0)),"")`;
  - `counted` «Учёт» = `=IF([@[Кол-во]]="",[@[Сумма ВОР]],[@[Кол-во]])` — то же правило, что в РИМ/ВД:
    количество акта, а если пусто — сумма ВОР.

Формулы без XLOOKUP/LET — работают в Excel 2019.

### Лист «Закрытие по актам»

Не умная таблица, а отчётный лист, перестраиваемый кнопкой «Обновить» (как ОЖР): строка шапки и строки позиций
спецификации по порядку: № п/п, Наименование, Ед., По проекту, Закрыто, Остаток, затем по столбцу на каждый акт
(заголовок «Акт №… от дд.мм.гггг»), значения — сумма «Учёт» материалов акта, привязанных к позиции. Пустые ячейки — пусто,
не 0. Разделы — строками-заголовками (жирным) перед своими позициями. Отрицательный остаток — красным.

`SCHEMA_VERSION` → 6. «Обновить разметку» добавляет лист «Спецификация», лист «Закрытие по актам», новые столбцы
в конец таблиц; данные не меняются.

## 2. Загрузка из РКЦ

Экран «Спецификация» в панели, кнопка «Загрузить из РКЦ»:

1. Пользователь выбирает .xlsx; файл уходит на сервер (`POST /api/files`, уже есть).
2. `GET /api/rkc/:fileId` → список листов книги. Пользователь выбирает лист (по умолчанию первый).
3. `GET /api/rkc/:fileId?sheet=<имя>` → разобранные позиции `{ number, section, name, unit, quantity }[]` и
   предупреждения.
4. Панель сравнивает с текущей спецификацией (`mergeSpec`, shared) и показывает предпросмотр: новые / изменённые /
   пропавшие из РКЦ / без изменений. «Применить» записывает в книгу.

### Чтение .xlsx на сервере

Без новых зависимостей (npm-реестр недоступен при сборке): .xlsx — zip; модуль `server/src/xlsx/read.ts` читает
центральный каталог zip, распаковывает записи `zlib.inflateRawSync`, разбирает `xl/workbook.xml` (+ rels) для имён
листов, `xl/sharedStrings.xml` и `xl/worksheets/sheetN.xml` (ячейки `c r=… t=…`, значения `v`/`is/t`). Формулы не
вычисляются — берётся сохранённое значение `v` (Excel его сохраняет). Объединения ячеек не нужны.

### Разбор листа (`parseRkc`, shared — чистая функция над матрицей значений)

- Шапка: первая строка, где есть ячейки, начинающиеся с «№П/П»/«№ п/п», «НАИМЕНОВАНИЕ», «ЕД. ИЗМ», «КОЛ-ВО»
  (без учёта регистра и пробелов). Из неё — индексы столбцов. Нет шапки → ошибка «Не найдена шапка РКЦ…».
- Строки ниже шапки:
  - служебная строка нумерации столбцов (1, 2, 3, 4, 7, 8…) и строки подзаголовков шапки — пропуск;
  - есть наименование, нет ед. изм. и кол-ва → раздел (запоминается как текущий `section`);
  - есть наименование и ед. изм. → позиция (кол-во может быть пустым — тогда 0 с предупреждением);
  - наименование начинается с «Всего», «Итого», «НДС», «Зачет/Зачёт аванса», «Гарантийное удержание», «к оплате»,
    либо это «---» → пропуск;
  - пустые строки — пропуск.
- Номер: текст ячейки, обрезанный; числа без дробной части — как целое («1»). Пустой → «б/н-N» + предупреждение
  «Позиция без №п/п: <наименование> — присвоен б/н-N». Повтор номера → предупреждение, вторая позиция получает
  «<номер>-2».

### Слияние (`mergeSpec`, shared)

По «№ п/п»:
- есть в книге и в РКЦ → обновить Раздел, Наименование, Ед., Кол-во; Источник = «РКЦ»; снять пометку «нет в РКЦ»;
- только в РКЦ → новая строка, Источник «РКЦ»;
- только в книге, Источник «РКЦ» → строка остаётся, в Примечание дописывается «нет в РКЦ» (если ещё нет);
- только в книге, Источник «вручную» → не трогается.

Порядок строк после слияния — порядок РКЦ, ручные строки остаются после позиции, за которой стояли (или в конце).
Привязки материалов не трогаются (они в «Материалах»).

«б/н-N» сопоставляются с прежними «б/н-N» по наименованию, а не по номеру.

## 3. Подбор №п/п

Экран «Материалы» → кнопка «Подобрать № п/п» (`matchSpec`, shared):
- для каждого материала без «№ п/п РКЦ» — лучшая позиция спецификации по сходству;
- нормализация: нижний регистр, «ё»→«е», латинские двойники кириллицы (а/a, е/e, о/o, р/p, с/c, х/x, н/h, к/k, м/m,
  т/t, в/b) приводятся к одному виду, «,»→«.», «×»/«х» между цифрами → «x», лишние пробелы и кавычки убираются;
- токены: слова и «марки» (последовательности с цифрами, например «ппгнг(a)-hf», «3x1.5»);
- оценка: доля совпавших токенов материала (наименование + марка) в токенах позиции, токены с цифрами весят вдвое;
- в список попадают совпадения ≥ 50 %, сортировка по убыванию; галочка по умолчанию у ≥ 70 %;
- окно: «материал → № п/п · наименование позиции · процент», «Применить отмеченные».

## 4. Разбивка и контроль

- Карточка строки «Спецификации»: «По проекту / Закрыто / Остаток» и список «Акт №… — N ед.» (из книги, тот же расчёт,
  что в формулах, — `specClosed`, shared). Материалы, привязанные к позиции, — списком.
- Карточка строки «Материалы в актах»: позиция РКЦ материала и «по проекту / закрыто / остаток»; если остаток < 0 —
  предупреждение «Закрыто больше, чем по проекту, на N».
- Проверка перед печатью акта: материал акта без «№ п/п РКЦ» при непустой спецификации — предупреждение (не ошибка),
  печать не блокирует. Пустая спецификация — проверки нет.
- Неизвестный «№ п/п РКЦ» в «Материалах» (нет в спецификации) — ошибка ячейки, как у других ссылок.

## 5. Тесты

- `xlsx.read`: минимальный .xlsx, собранный в тесте через `zlib.deflateRawSync`,
  имена листов, общие строки, числа, inline-строки.
- `rkc.parse`: обезличенная выборка 15 строк в форме РКЦ (шапка в 2 строки, нумерация столбцов, разделы, позиция без
  номера, итоги/НДС/аванс) — позиции, разделы, предупреждения.
- `spec.merge`: обновление, новые, пропавшие, ручные, «б/н».
- `spec.match`: «ППГнг(А)-HF 3х1,5» ↔ «Кабель … ППГнг(А)-НF 3x1.5», кириллица/латиница, пороги.
- `spec.closed`: закрыто по актам с правилом «Кол-во или ВОР», разбивка по актам, лист «Закрытие по актам».
- Схема: формулы столбцов, обновление разметки v5 → v6.
- Сервер: `/api/rkc/:id` — листы и разбор; не-xlsx → 422 «Это не файл Excel (.xlsx)».

Реальный РКЦ пользователя в репозиторий не кладётся (коммерческие цены).

## Вне объёма

- Цены, суммы, стоимость закрытого.
- Формат .xls (старый Excel) — пользователь сохраняет как .xlsx; панель так и подскажет.
- Автоматическое закрытие работ/услуг (они остаются позициями с остатком, закрываются только если к ним привязать
  материал/работу из актов).
