# Этап 0 плана развития: скорость, порядок в коде, библиотека компании, нужные листы, мастер первого акта

Дата: 25.10.2026. Источник: документ «Конструктор ИД: развитие продукта», раздел «Упростить и ускорить», пункты 1–6
(пункт 7 «Импорт замеров» — исключён пользователем). Одобрено пользователем 25.10.2026.

## 1. Цель и критерий готовности

Этап 0 даёт пользу текущим пользователям (компания владельца, все места с MS Excel) до общего сервера и готовит код к нему.
Готово, когда новый пользователь в пустой книге печатает первый АОСР без помощи, а панель не подтормаживает на книге с
500+ строками материалов.

Три плана, каждый — отдельная ветка, тесты зелёные после каждой задачи; в конце — один установщик 0.17.

| План | Что | Видно пользователю |
| --- | --- | --- |
| 15 | Быстрое чтение книги; удаление наследия 0.2; одно описание документов акта | скорость; пропадает «Перенос из базы 0.2» |
| 16 | Библиотека компании в папке (локальной или сетевой) | раздел «Библиотека», «В библиотеку», настройка папки |
| 17 | Только нужные листы; мастер первого акта | переключатель листов, мастер в пустой книге |

## 2. План 15

### 2.1 Быстрое чтение книги

- `TableStore.readMany?(names)` (необязательный): все таблицы за один `Excel.run` — заголовки и значения одним `sync`,
  гиперссылки столбцов типа file всех таблиц — вторым `sync`. Сейчас: 34 таблицы × 2–3 `sync` + `sync` на каждую ячейку-ссылку.
- `readBook(store)` использует `readMany`, если он есть, иначе как раньше. Новая `bookFromTables(map)` собирает `Book` из
  прочитанных таблиц; `readBook` = чтение + `bookFromTables`.
- Панель (`useBook`) хранит прочитанные таблицы. Изменение ячеек одной нашей таблицы (событие знает таблицу) → перечитать
  только её и пересобрать `Book`. Полное перечитывание: открытие, «Обновить», событие вне наших таблиц или без таблицы,
  смена числа таблиц (разметка), ошибка частичного чтения.
- Поведение `Book` не меняется: те же строки, ссылки, `missing`.

### 2.2 Наследие версии 0.2

Удаляются: маршрут `/api/export`, `print/fromDb.ts`, `print/data.ts` (`buildDocData`), `seed/sbdAov1.ts`,
`scripts/seed-sbd.ts`, репозитории старых таблиц (`repo/acts|crud|materials|objectInfo|organizations|qualityDocs|
representatives|sections`), перенос `exportToBook/exportLinks/ExportData/isEmptyExport` и шаг «Перенести» в `CreateBook`.
Остаются: миграции SQL (история базы не переписывается, старые таблицы просто не читаются), таблица `files`, справочник
нормативов (`repo/normCatalog.ts`, `repo/util.ts` если нужен ему). `writeBook` переезжает в `workbook/write.ts` (он нужен
примерам новой книги, библиотеке и мастеру). Тесты печати, построенные на базе 0.2, переводятся на книгу-образец
`aov1Records` с теми же проверками; тесты переноса удаляются; `/api/export` → 404 в тесте удалённых маршрутов.

### 2.3 Одно описание документов акта

`shared/src/docs/defs.ts` — `ACT_DOC_DEFS: Record<ActDocKind, ActDocDef>` для `aosr, rim, vd, vor, avk, kj, ip, rp`
(протоколы плана 13 остаются в `PROTO_DEFS`):

| Поле | Смысл |
| --- | --- |
| `kind`, `label` | вид печати и подпись в шаблоне («АОСР», «РИМ», …, «РП») |
| `registry` | вид строки реестра («АОСР», «РИМ», «ВД», «ВОР», «АВК», «КЖ», «Протокол», «РП») |
| `suffix: Record<FormSet,string>` | суффикс номера (как `docNumberFor` сейчас) |
| `name: Record<FormSet,string>` | наименование строки реестра |
| `bundle: "act" \| "cable"` | какой пакет нужен печати |
| `tables: TableName[]` | таблицы книги, из которых документ берёт данные (для «нужных листов», план 17) |
| `formDoc?: FormDoc` | у каких документов форма выбирается по набору (vd, rim, kj) |

Сервер: `server/src/print/docs.ts` — `ACT_DOC_RENDER: Record<ActDocKind, Partial<Record<FormSet, render>>>`, где
`render(b, options) → { html, pageNumbers? }`; имя файла — из `ACT_DOC_DEFS` (`fileName(b, set)`, поведение как сейчас:
ВОР — «<акт>.ВОР», АВК — «АВК <номер>», КЖ «СБД» — шифр журнала или «<акт>.КЖ», протокол «СБД» — «<акт>.Протокол»).
`renderBundlePdf` = выбор формы `formOf(options, formDoc) ` (документ без `formDoc` — по набору, если форма набора есть, иначе
«СБД») + `render` + имя. `docNumberFor`, наименования реестра, `PRINTED_KINDS`, подписи `BUILTIN_DOC_LABELS` берутся из
`ACT_DOC_DEFS`. Тексты, номера, формы и файлы — без изменений; это проверяет весь существующий набор тестов.

## 3. План 16 — библиотека компании

### 3.1 Хранилище

- Папка библиотеки: настройка сервера `libraryDir` в `<dataDir>/settings.json`; по умолчанию `<dataDir>/library`.
  Можно указать сетевую папку (`\\server\ИД\Библиотека`) — тогда библиотека общая у всех ПК, указавших её.
- Запись — отдельный файл `<вид>/<id>.json` (`id` — UUID), поэтому одновременные добавления с разных ПК не конфликтуют;
  запись файла — во временный файл и переименование. Виды: `org`, `rep`, `material`, `doc`.
- Значения записи — по ключам столбцов таблиц книги: `org` ↔ «Организации», `rep` ↔ «Представители», `material` ↔
  «Материалы», `doc` ↔ «ДокументыКачества» (служебные и формульные столбцы не хранятся). У `doc` — `scan`: `sha256` и имя
  файла; файл скана — `files/<sha256>` в папке библиотеки. Поле `updatedAt`, `updatedBy` (имя ПК/пользователя ОС).
- Естественные ключи (повтор = обновление существующей записи, не дубль): организация — ИНН, без ИНН — краткое
  наименование; представитель — ФИО + организация; материал — наименование + марка; документ — вид + номер.
- Папка недоступна (сеть отключена) — понятная ошибка «Папка библиотеки недоступна: <путь>», книга работает как обычно.

### 3.2 API сервера

`GET /api/library/settings`, `PUT /api/library/settings {dir}` (папка создаётся; проверка записи) ·
`GET /api/library/:kind?q=` (поиск без учёта регистра по текстовым полям, до 200 записей) ·
`POST /api/library/:kind {values, fileId?}` (добавить/обновить по ключу; `fileId` — скан из локального хранилища, копируется
в библиотеку) → `{id, created}` · `DELETE /api/library/:kind/:id` ·
`POST /api/library/files/:sha/import` → скан копируется в локальное хранилище файлов → `{fileId}`.

### 3.3 Панель

- Раздел «Библиотека» (кнопка в верхней строке): вкладки «Организации», «Представители», «Материалы», «Документы качества»;
  поиск; отметки строк; «Добавить в книгу».
- «Добавить в книгу»: строки вставляются в таблицы книги; уже есть в книге по тому же ключу — пропуск (в итоге «добавлено N,
  уже были M»). Материал тянет свои документы качества (по столбцу «Материалы» документа), представитель — свою
  организацию. Сканы — `import` и ссылка на локальный файл, как при обычной загрузке.
- «В библиотеку»: в «Функционале таблицы» у четырёх таблиц — для выделенных строк (или строки под курсором). Документ
  отправляется со сканом. Итог «добавлено N, обновлено M».
- «Настройки» → «Папка библиотеки» с проверкой.

## 4. План 17

### 4.1 Только нужные листы

- Нужные таблицы книги = всегда нужные («Объект», «Организации», «Шифры», «Представители», «Материалы»,
  «ДокументыКачества», «Акты», «Схемы», «МатериалыАктов», «Комплекты», «АктыКомплектов», «РеестрИД») ∪ `tables` документов
  шаблона книги (`ACT_DOC_DEFS`, протоколы — `PROTO_DEFS[...].table` + «Протоколы», «ПереченьОборудования») ∪ «ОЖР3»,
  «ОЖР5», «Спецификация» (общие разделы ИД — нужны всегда). Свои документы шаблона таблиц не добавляют.
- Лист скрывается, если ни одна его таблица не нужна и в его таблицах нет строк данных. «Реквизиты» не скрывается никогда.
- Настройка книги `idk.neededSheets` («1»/«0», по умолчанию «0» — книги не меняются без спроса). Переключатель «Только
  нужные листы» в «Функционале листа»; при включении и при выборе шаблона для книги — пересчёт; при выключении — все листы
  видимы. Функция `neededSheets(template, book) → {visible, hidden}` — чистая, в shared.

### 4.2 Мастер первого акта

- Показывается в панели в книге без актов (кнопка «Мастер первого акта»; в «Функционале листа» «Базы актов» — всегда).
- Шаги: 1) объект — поля «Объекта», которые нужны АОСР; 2) участники — организации по ролям АОСР (из библиотеки или
  вручную) и их представители; 3) шифр раздела; 4) материалы (из библиотеки или вручную), количество; 5) акт — номер,
  работы, даты начала/окончания, раздел → «Создать акт» → строки в листах → «Печать АОСР».
- Мастер пишет в те же таблицы через `TableStore` (`writeBook`/`insert`); проверка — тот же `buildBundle`; ошибки шага
  показываются у поля. «Назад» не теряет введённое; закрытие мастера оставляет записанное в книге.

## 5. Риски и проверки

1. Частичное перечитывание пропустило изменение (вставка строк Excel в таблицу, вставка блока через две таблицы) —
   книга совпадает с полным чтением. Тест на модели.
2. Удаление наследия не задело справочник нормативов и сканы. Тест: старые тесты норм и файлов зелёные.
3. Рефакторинг описаний: имена файлов, номера, наименования реестра и HTML всех документов «СБД» и «ТИ» — как до него.
4. Библиотека: две записи с одним ключом с «разных ПК» (два сервера на одной папке) — одна запись, последняя правка.
   Папка недоступна — ошибка, панель работает.
5. «Добавить в книгу» дважды — без дублей; материал с документом, который уже есть, — документ не дублируется.
6. Нужные листы не скрывают лист с данными и не скрывают ничего при выключенной настройке.
7. Мастер: книга после мастера печатает АОСР без ошибок `buildBundle`.

## 6. Вне этапа

Импорт замеров (исключён). Общий сервер, учёт пользователей, нейросеть — этапы 1–3.
