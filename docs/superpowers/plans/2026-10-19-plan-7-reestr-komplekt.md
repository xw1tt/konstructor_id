# План 7 — замечания к печати, Реестр ИД и комплект в один PDF

Спецификация: `docs/superpowers/specs/2026-10-19-reestr-komplekt-design.md`.
Выполнение — inline, TDD (тест → красный → код → зелёный → коммит), журнал в
`.superpowers/sdd/plan-7/progress.md`. После всех задач — независимое ревью, один проход исправлений.

## Задачи

**T1. Повторы в «Представителях» (§2.1).** `TableDef.allowDuplicates` у «Представителей»;
`buildBundle` не вызывает `checkDuplicates` для них; `paint` не ставит правило повтора; подсказка ФИО.
Тесты: две строки «Иванов И.И.» в разных и одинаковых ролях — пакет без ошибок; схема помечена.

**T2. Важное в «Объекте» (§2.2).** Экспорт `OBJECT_REQUIRED` и `objectFieldImportant(label)`;
`objectImportantRule(fieldCol, valueCol, firstRow, labels)` — правило только для строк обязательных
полей; `paint` для «Объекта»; карточка: «*» у «Значения» только для обязательных полей.
Тесты: формула правила; `objectFieldImportant`.

**T3. Документ качества без даты (§2.3).** «Дата» не важна; РИМ — «б/д». Тесты: пакет без даты без
ошибок; `rimRows` → «б/д»; п.3 без «от».

**T4. Группы РИМ (§2.4).** `RimRow.cont` (продолжение группы материала) и `RimRow.group` (номер
группы); шаблон: `<tbody class="grp">` на группу, `break-inside: avoid`, ячейка наименования у
продолжений пустая, границы между ячейками группы убраны. Тесты: строки АОВ1 (наименование один раз
на материал); HTML.

**T5. Норматив с наименованием (§2.5).** `appendNorm(current, designation, text)`; `normInsertText(item,
mode)`; переключатель в `NormativScreen` (localStorage `idk.normInsert`). Тесты: оба режима, повтор по
обозначению.

**T6. Настройка п.4 (§2.6).** `PrintOptions { schemeEach }` (настройка книги `idk.print`),
`point4Lines(docs, opts)`; `PrintRequest.options`; меню «Шаблоны ▾» — флажок; `printAct` передаёт.
Тесты: оба режима; запрос печати с options.

**T7. Схема книги (§3.1–3.3).** Поле «Папка сканов»; «Логотип»; «Скан» в лаборатории и СИ; таблицы
`Комплекты`, `АктыКомплектов`, `РеестрИД`; листы «Комплекты», «Реестр ИД»; подсказки и примеры;
`SCHEMA_VERSION = 2`; раздел панели «Комплекты». `ensureBook`: недостающие столбцы (в конец), поля
«Объекта», перекраска всех таблиц. Чистые помощники `missingColumns`, `missingObjectFields`. Тесты.

**T8. «Заполнить из актов» (§3.4).** `shared/kit/registry.ts`: `registryRows(book, kit)` →
записи по заголовкам (+ ссылки сканов); `fillRegistry(store, book, kit)`. Тесты на АОВ1: 6+1+… строк,
номера/наименования/даты как в образце; документы качества; дедупликация на два акта; замена строк
комплекта на месте.

**T9. Запрос сборки (§4.1–4.2).** `shared/kit/request.ts`: zod `KitRequest`; `buildKitRequest(book, kit,
important, template, options)` → `{ request | null, issues }` (пакеты актов, кабели, сканы с запасным
поиском, логотипы, проверки). Тесты.

**T10. Файлы сервера (§4.3).** `server/src/kit/files.ts`: `resolveScan(ref, ctx)` — ссылка
`/api/files/N`, путь в папке, полный путь, расширения; `loadPages(file)` — PDF/картинка → документ
pdf-lib; ошибки. Тесты.

**T11. Шаблоны реестра, титула, корешков (§5).** `templates/registry.ts`, `cover.ts`, `spine.ts`,
стили. Тесты текста HTML.

**T12. Сборка и маршрут (§4.3–4.4).** `renderBundlePdf(b, kind, options)` (вынести из
`sendBundlePdf`); `server/src/kit/assemble.ts` — печать документов, листы, «л.», реестр, титул,
корешки, склейка; `POST /api/kit-jobs` (лимит тела 20 МБ, 422 со списком ошибок файлов) и
`GET /api/kit-jobs/:id`. Тесты: порядок и число страниц, «л. 1-3», текст реестра, ошибки.

**T13. Панель (§4).** `KitExtras`: «Заполнить из актов» (подтверждение), «Реестр» (фильтр),
«Собрать комплект» (ошибки — список со ссылками на ячейки, как у печати акта); карточки
«Комплектов», «АктовКомплектов», «Реестра ИД»; умолчания новых строк («Комплект» — последний
выбранный/единственный). Тесты чистых функций.

**T14. Выпуск.** README (пункты проверки 20–22, версия 0.7), сверка с образцом (скриншоты), ревью,
исправления, архив.
